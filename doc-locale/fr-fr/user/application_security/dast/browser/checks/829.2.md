## Description {#description}

Des fichiers sources JavaScript ou CSS ont été trouvés contenant des valeurs [Sub-Resource Integrity (SRI)](https://developer.mozilla.org/en-US/docs/Web/Security/Subresource_Integrity) `integrity` non valides ou une valeur `crossorigin` manquante. Ces scripts ou liens doivent être examinés pour s'assurer qu'ils n'ont pas été modifiés de manière malveillante. En cas de doute, contactez le propriétaire des scripts ou remplacez-les par des versions connues comme fiables.

## Remédiation {#remediation}

Toutes les ressources identifiées doivent provenir du même domaine que l'application cible. Si cela n'est pas possible, il est fortement recommandé que toutes les balises `script` implémentant des valeurs `src`, ou les balises `link` implémentant les valeurs `href` incluent la Sub-Resource Integrity. Pour générer des valeurs d'intégrité SRI, l'outil [SRI hash](https://www.srihash.org/) peut être utilisé, ou en exécutant l'une des commandes suivantes :

- `cat FILENAME.js | openssl dgst -sha384 -binary | openssl base64 -A`
- `shasum -b -a 384 FILENAME.js | awk '{ print $1 }' | xxd -r -p | base64`

La sortie de ces outils doit être ajoutée en tant qu'attributs supplémentaires, en particulier : `integrity` et soit `crossorigin=anonymous` soit `crossorigin=use-credentials`. Un exemple de balise de script protégée par SRI valide est présenté ci-dessous :

```html
<script src="https://example.com/example-framework.js"
    integrity="sha384-oqVuAfXRKap7fdgcCY5uykM6+R9GqQ8K/uxy9rx7HNQlGYl1kPzQho1wx4JwY8wC"
    crossorigin="anonymous"></script>
```
