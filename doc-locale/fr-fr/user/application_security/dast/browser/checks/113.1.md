## Description {#description}

En insérant des caractères de retour chariot/saut de ligne (CRLF), des utilisateurs malveillants pourraient potentiellement injecter des données arbitraires dans les réponses HTTP. En modifiant les réponses HTTP, des attaquants pourraient mener des attaques de type cross-site scripting ou des attaques d'empoisonnement de cache contre d'autres utilisateurs du système.

## Remédiation {#remediation}

Les saisies utilisateur ne doivent jamais être utilisées dans la construction des réponses d'en-tête HTTP sans une forme de validation contre les nouvelles lignes. Cela inclut les URL fournies par l'utilisateur pour les redirections HTTP.
