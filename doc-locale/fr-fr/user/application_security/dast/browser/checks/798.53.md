## Description {#description}

Le corps de la réponse contient du contenu correspondant au modèle d'un GitHub OAuth Access Token qui a été identifié. Contrairement à un jeton OAuth traditionnel, les jetons d'accès utilisateur n'utilisent pas de portées. À la place, il utilise des permissions précises. Un jeton d'accès utilisateur ne dispose que des permissions accordées à la fois à l'utilisateur et à l'application. Si un acteur malveillant accède au jeton et que l'application s'est vu accorder la permission d'écrire le contenu d'un dépôt, mais que l'utilisateur ne peut que lire le contenu, alors le jeton d'accès utilisateur ne peut que lire le contenu. L'exposition de cette valeur pourrait permettre à des attaquants d'accéder à toutes les ressources accordées par ce jeton.

## Remédiation {#remediation}

Pour des conseils généraux sur la gestion des incidents de sécurité concernant les clés exposées, veuillez consulter la documentation GitLab sur [l'exposition des identifiants sur Internet](../../../../../security/responding_to_security_incidents.md#credential-exposure-to-public-internet). Pour plus d'informations, veuillez consulter [la documentation GitHub pour révoquer des jetons d'accès OAuth](https://docs.github.com/en/rest/apps/oauth-applications?apiVersion=2022-11-28#delete-an-app-token). Notez également que les GitHub Apps sont préférées aux applications OAuth ; veuillez consulter [la documentation GitHub pour plus de détails](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/differences-between-github-apps-and-oauth-apps).
