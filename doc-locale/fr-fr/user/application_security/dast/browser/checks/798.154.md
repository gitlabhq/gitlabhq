## Description {#description}

Le corps de la réponse contient du contenu correspondant au modèle d'un jeton batch HashiCorp Vault. Les jetons batch sont utilisés lorsque des centaines, voire des milliers de systèmes doivent accéder à Vault, mais que la génération de jetons uniques ne serait pas scalable. Ces jetons sont généralement de courte durée de vie et liés à une politique Vault spécifique. Un acteur malveillant ayant accès à ce jeton peut usurper l'identité d'un service et disposer des mêmes niveaux de permissions que la politique pour laquelle le jeton batch a été créé. L'exposition de cette valeur pourrait permettre à des personnes malveillantes d'accéder à toutes les ressources accordées par ce jeton.

## Remédiation {#remediation}

Pour des conseils généraux sur la gestion des incidents de sécurité liés aux clés compromises, veuillez consulter la documentation GitLab sur [l'exposition des identifiants sur Internet](../../../../../security/responding_to_security_incidents.md#credential-exposure-to-public-internet). Les jetons batch ne peuvent pas être révoqués ; vous devez donc utiliser des valeurs « time to live » très courtes lors de la création de jetons batch. Pour plus d'informations, veuillez consulter [la documentation de Vault sur les jetons batch](https://developer.hashicorp.com/vault/tutorials/tokens/batch-tokens).
