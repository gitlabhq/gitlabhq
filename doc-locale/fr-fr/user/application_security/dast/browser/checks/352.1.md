## Description {#description}

L'application n'a pas réussi à se protéger contre les attaques de type Cross-Site Request Forgery (CSRF) en utilisant des jetons d'application sécurisés ou des directives de cookie `SameSite`.

La vulnérabilité peut être exploitée par un attaquant qui crée un lien ou un formulaire sur un site tiers et incite une victime authentifiée à y accéder.

## Remédiation {#remediation}

Envisagez de configurer tous les cookies de session avec l'attribut `SameSite=Strict`. Il convient toutefois de noter que cela peut avoir un impact sur la convivialité lors du partage de liens via d'autres supports. Il est recommandé d'adopter une approche basée sur deux cookies, telle que décrite dans la section [Top level navigations](https://datatracker.ietf.org/doc/html/draft-ietf-httpbis-rfc6265bis-08#section-8.8.2) du RFC.

Si l'application utilise un framework courant, il est possible que la protection anti-CSRF soit intégrée mais qu'elle doive être activée. Consultez la documentation de votre framework d'application pour plus de détails.

Si aucune de ces options n'est applicable, il est **fortement** recommandé d'utiliser une bibliothèque tierce. La mise en œuvre d'un système anti-CSRF sécurisé représente un investissement conséquent et est difficile à réaliser correctement.
