## Description {#description}

L'application cible s'est révélée vulnérable à l'injection de code. Un acteur malveillant pourrait injecter du code Ruby arbitraire pour l'exécuter sur le serveur. Cela pourrait conduire à une compromission totale du système en accédant à des secrets stockés, en injectant du code pour prendre le contrôle de comptes ou en exécutant des commandes OS.

## Remédiation {#remediation}

Ne transmettez jamais directement des entrées utilisateur à des fonctions qui évaluent des données de type chaîne en tant que code, telles que `eval`, `send`, `public_send`, `instance_eval` ou `class_eval`. Il n'existe presque aucun avantage à transmettre des valeurs de type chaîne à ces méthodes ; aussi, la meilleure recommandation est de remplacer la logique actuelle par des implémentations plus sûres permettant d'évaluer dynamiquement la logique avec des entrées utilisateur. Si vous utilisez `send` ou `public_send`, assurez-vous que le premier argument correspond à une méthode/un symbole connu(e) et codé(e) en dur, et qu'il ne provient pas d'une entrée utilisateur.

Pour `eval`, `instance_eval` et `class_eval`, les entrées utilisateur ne doivent jamais être envoyées directement à ces méthodes. Une alternative consiste à stocker des fonctions ou des méthodes dans un Hash pouvant être recherché à l'aide d'une clé. Si la clé existe, la fonction peut être exécutée.

```ruby
def func_to_run
  puts 'hello world'
end

input = 'fn'

function_map = { fn: method(:func_to_run) }

if function_map.key?(input.to_sym)
  function_map[input.to_sym].call
else
  puts 'invalid input'
end
```
