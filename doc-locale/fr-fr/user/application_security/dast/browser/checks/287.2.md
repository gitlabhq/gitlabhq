## Description {#description}

L'application cible a été identifiée comme authentifiant les utilisateurs via le schéma d'authentification Digest sur HTTP. L'authentification Digest utilise un algorithme de hachage non sécurisé (MD5) pour hacher le nom d'utilisateur et le mot de passe, puis les envoie dans l'en-tête `Authentication`. Des attaquants positionnés entre le client et le serveur dans le chemin de communication (ou sur le même réseau local) pourraient utiliser des renifleurs de paquets pour modifier les paramètres de réponse du serveur et ainsi abaisser le niveau de sécurité du mode d'authentification Digest. De plus, le serveur stocke les informations d'identification hachées, généralement dans un fichier appelé `.htpasswd`. Des outils sont facilement disponibles pour craquer ces mots de passe.

## Remédiation {#remediation}

Si possible, adoptez une méthode plus robuste pour authentifier les utilisateurs, telle qu'OAuth 2.0, ou stockez les noms d'utilisateur et les mots de passe dans un entrepôt de données protégé par l'algorithme Argon2id. Si l'authentification Digest doit être utilisée, assurez-vous que les informations d'identification ne sont transmises que via des canaux sécurisés tels que HTTPS/TLS.
