## Description {#description}

Le Cross Site Scripting (XSS) est une attaque qui exploite une application ou un système web pour traiter les données saisies par l'utilisateur comme du code de balisage ou du code script. Il est important d'encoder les données en fonction du contexte spécifique dans lequel elles sont utilisées. Il existe au moins six types de contextes :

- Dans les balises HTML `<div>context 1</div>`
- Dans les attributs : ```<div class="context 2"></div>```
- Dans les attributs d'événements ```<button onclick="context 3">button</button>```
- Dans les blocs script : ```<script>var x = "context 4"</script>```
- Affectation HTML non sécurisée à un élément : ```element.innerHTML = "context 5"```
- Dans les URL : ```<iframe src="context 6"></iframe><a href="context 6">link</a>```

Les blocs script seuls peuvent être encodés de plusieurs façons. Faites preuve de prudence si les données saisies par l'utilisateur doivent être écrites en dehors des balises script.

## Remédiation {#remediation}

Les données saisies par l'utilisateur et affichées dans l'application doivent être encodées, assainies ou validées afin de ne pas être traitées comme du HTML ou exécutées comme du code JavaScript. Veillez à ne pas mélanger les templates côté serveur avec les templates côté client, car le côté serveur n'encode pas le texte tel que `{{ 7*7 }}`, qui pourrait exécuter des fonctionnalités côté client.

N'encodez pas les données saisies par l'utilisateur avant de les insérer dans un entrepôt de données. Les données doivent être encodées en fonction de leur contexte de sortie. Il est beaucoup plus sûr de forcer le système d'affichage à gérer l'encodage.

Envisagez d'utiliser les fonctionnalités intégrées du framework pour encoder automatiquement les données saisies par l'utilisateur. Si vous ne pouvez pas encoder automatiquement les données saisies, veillez à utiliser l'encodage de sortie approprié. Les recommandations suivantes constituent une approche optimale et peuvent ne pas fonctionner dans toutes les circonstances.

- Encodez les éléments suivants dans les balises HTML, à l'exclusion de `script` :
  - `<` en `&lt;`
  - `>` en `&gt;`
  - `'` en `&apos;`
  - `"` en `&quot;`
  - `=` en `&#61;`
- Encodez les éléments suivants dans les attributs, à l'exclusion des attributs d'événements :
  - `<` en `&lt;`
  - `>` en `&gt;`
  - `'` en `&apos;`
  - `"` en `&quot;`
  - `=` en `&#61;`
- Encodez les éléments suivants dans les attributs d'événements, les blocs script et les affectations HTML non sécurisées :
  - Tabulation littérale (`\t`) en `\\t`
  - Nouvelle ligne littérale (`\n`) en `\\n`
  - Tabulation verticale littérale (`\v`) en `\u000b`
  - Saut de page littéral (`\f`) en `\\f`
  - Retour chariot littéral (`\r`) en `\\r`
  - Signe égal littéral (`=`) en `\u0061`
  - Accent grave littéral (`\`) en `\u0060`
  - Guillemet double littéral (`"`) en `\u0022`
  - Esperluette littérale (`&`) en `\u0026`
  - Guillemet simple littéral (`'`) en `\u0027`
  - Symbole plus littéral (`+`) en `\u002b`
  - Barre oblique littérale (`/`) en `\/`
  - Symbole inférieur à littéral (`<`) en `\u003c`
  - Symbole supérieur à littéral (`>`) en `\u003e`
  - Parenthèse ouvrante littérale (`(`) en `\u0028`
  - Parenthèse fermante littérale (`)`) en `\u0029`
  - Crochet ouvrant littéral (`[`) en `\u005b`
  - Crochet fermant littéral (`]`) en `\u005d`
  - Accolade ouvrante littérale (`{`) en `\u007b`
  - Accolade fermante littérale (`}`) en `\u007d`
  - Barre oblique inverse littérale (`\`) en `\\`

  Cette liste n'est pas exhaustive. Vous pourriez avoir besoin d'encoder des caractères supplémentaires en fonction du contexte.
- Dans les URL :
  - Ne permettez jamais que les données saisies par l'utilisateur soient imprimées dans des URL. Les attaquants pourraient injecter du code `javascript:...` ou des liens malveillants.
