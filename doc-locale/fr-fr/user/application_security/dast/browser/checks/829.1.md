## Description {#description}

Les fichiers sources JavaScript ou CSS sont inclus depuis des domaines tiers sans [Sub-Resource Integrity (SRI)](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Subresource_Integrity). Si un attaquant venait à compromettre les sites hébergeant ces ressources tierces, il pourrait injecter des scripts malveillants ou des données CSS dans le but de compromettre les utilisateurs de votre application. Cependant, si le SRI est appliqué et qu'un attaquant tente de modifier le contenu du script, le navigateur ne chargera pas le script et les utilisateurs de votre application seront protégés des modifications malveillantes.

## Remédiation {#remediation}

Toutes les ressources identifiées doivent provenir du même domaine que l'application cible. Si cela n'est pas possible, il est fortement recommandé que toutes les balises `script` qui implémentent des valeurs `src`, ou les balises `link` qui implémentent les valeurs `href` incluent le Sub-Resource Integrity. Pour générer des valeurs d'intégrité SRI, l'outil [SRI hash](https://www.srihash.org/) peut être utilisé, ou en exécutant l'une des commandes suivantes :

- `cat FILENAME.js | openssl dgst -sha384 -binary | openssl base64 -A`
- `shasum -b -a 384 FILENAME.js | awk '{ print $1 }' | xxd -r -p | base64`

La sortie de ces outils doit être ajoutée en tant qu'attributs supplémentaires, en particulier : `integrity` et soit `crossorigin=anonymous` soit `crossorigin=use-credentials`. Un exemple de balise de script protégée par SRI valide est présenté ci-dessous :

```html
<script src="https://example.com/example-framework.js"
    integrity="sha384-oqVuAfXRKap7fdgcCY5uykM6+R9GqQ8K/uxy9rx7HNQlGYl1kPzQho1wx4JwY8wC"
    crossorigin="anonymous"></script>
```
