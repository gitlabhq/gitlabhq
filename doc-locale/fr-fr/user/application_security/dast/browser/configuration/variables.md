Ces variables CI/CD sont spécifiques à l'analyseur DAST basé sur navigateur. Elles peuvent être utilisées pour personnaliser le comportement de DAST selon vos besoins.

## Comportement des scanners {#scanner-behavior}

Ces variables contrôlent la manière dont le scan est effectué et l'emplacement de stockage de ses résultats.

| Variable CI/CD | Type | Exemple | Description |
| :------------- | :--- | ------- | :---------- |
| `DAST_CHECKS_TO_EXCLUDE` | chaîne | `552.2,78.1` | Liste séparée par des virgules d'identifiants de vérification à exclure du scan. Pour les identifiants, voir [les vérifications de vulnérabilité](../checks/_index.md). |
| `DAST_CHECKS_TO_RUN` | Liste de chaînes | `16.1,16.2,16.3` | Liste séparée par des virgules d'identifiants de vérification à utiliser pour le scan. Pour les identifiants, voir [les vérifications de vulnérabilité](../checks/_index.md). |
| `DAST_CRAWL_GRAPH` | booléen | `true` | Définissez sur `true` pour générer un graphique SVG des chemins de navigation visités pendant la phase de crawl du scan. Vous devez également définir `gl-dast-crawl-graph.svg` comme artefact de job CI pour pouvoir accéder au graphique généré. Par défaut : `false`. |
| `DAST_FULL_SCAN` | booléen | `true` | Définissez sur `true` pour exécuter à la fois les vérifications passives et actives. La valeur par défaut est `false`. |
| `DAST_LOG_BROWSER_OUTPUT` | booléen | `true` | Définissez sur `true` pour journaliser `STDOUT` et `STDERR` de Chromium. |
| `DAST_LOG_CONFIG` | Liste de chaînes | `brows:debug,auth:debug` | (Obsolète) Liste de modules et de leur niveau de journalisation prévu pour le journal de la console. |
| `DAST_LOG_DEVTOOLS_CONFIG` | chaîne | `Default:messageAndBody,truncate:2000` | Définissez cette option pour journaliser les messages de protocole entre DAST et le navigateur Chromium. |
| `DAST_LOG_FILE_CONFIG` | Liste de chaînes | `brows:debug,auth:debug` | Liste de modules et de leur niveau de journalisation prévu pour le journal de fichier. |
| `DAST_LOG_FILE_PATH` | chaîne | `/output/browserker.log` | Définissez le chemin d'accès au journal de fichier. La valeur par défaut est `gl-dast-scan.log`. |
| `SECURE_ANALYZERS_PREFIX` | URL | `registry.organization.com` | Définissez l'adresse de base du registre Docker à partir de laquelle télécharger l'analyseur. |
| `SECURE_LOG_LEVEL` | chaîne | `debug` | Définissez le niveau par défaut pour le journal de fichier. Voir [SECURE_LOG_LEVEL](../troubleshooting.md#secure_log_level). |

## Éléments, actions et délais d'attente {#elements-actions-and-timeouts}

Ces variables indiquent au scanner où rechercher certains éléments, quelles actions entreprendre et combien de temps attendre pour que les opérations se terminent.

| Variable CI/CD | Type | Exemple | Description |
| :------------- | :--- | ------- | :---------- |
| `DAST_ACTIVE_SCAN_TIMEOUT` | [Chaîne de durée](https://pkg.go.dev/time#ParseDuration) | `3h` | La durée maximale d'attente pour que la phase de scan actif du scan se termine. Par défaut : 3h. |
| `DAST_ACTIVE_SCAN_WORKER_COUNT` | nombre | `3` | Le nombre de vérifications actives à exécuter en parallèle. Par défaut : 3. |
| `DAST_CRAWL_MAX_ACTIONS` | nombre | `10000` | Le nombre maximum d'actions effectuées par le crawler. Les exemples d'actions incluent la sélection d'un lien ou le remplissage d'un formulaire. Par défaut : `10000`. |
| `DAST_CRAWL_MAX_DEPTH` | nombre | `10` | Le nombre maximum d'actions chaînées effectuées par le crawler. Par exemple, `Click, Form Fill, Click` correspond à une profondeur de trois. Par défaut : `10`. |
| `DAST_CRAWL_TIMEOUT` | [Chaîne de durée](https://pkg.go.dev/time#ParseDuration) | `5m` | La durée maximale d'attente pour que la phase de crawl du scan se termine. Par défaut : `24h`. |
| `DAST_CRAWL_WORKER_COUNT` | nombre | `3` | Le nombre maximum d'instances de navigateur simultanées à utiliser. Pour les runners d'instance sur GitLab.com, nous recommandons un maximum de trois. Les runners privés disposant de plus de ressources peuvent bénéficier d'un nombre plus élevé, mais sont susceptibles de n'apporter que peu d'avantages au-delà de cinq à sept instances. La valeur par défaut est dynamique, égale au nombre de processeurs logiques utilisables. |
| `DAST_PAGE_DOM_READY_TIMEOUT` | [Chaîne de durée](https://pkg.go.dev/time#ParseDuration) | `7s` | La durée maximale d'attente pour qu'un navigateur considère une page comme chargée et prête à être analysée après la fin d'une navigation. Par défaut : `6s`. |
| `DAST_PAGE_DOM_STABLE_WAIT` | [Chaîne de durée](https://pkg.go.dev/time#ParseDuration) | `200ms` | Définissez la durée d'attente des mises à jour du DOM avant de vérifier si une page est stable. Par défaut : `500ms`. |
| `DAST_PAGE_ELEMENT_READY_TIMEOUT` | [Chaîne de durée](https://pkg.go.dev/time#ParseDuration) | `600ms` | La durée maximale d'attente pour un élément avant de déterminer s'il est prêt pour l'analyse. Par défaut : `300ms`. |
| `DAST_PAGE_IS_LOADING_ELEMENT` | [sélecteur](authentication.md#finding-an-elements-selector) | `css:#page-is-loading` | Sélecteur qui, lorsqu'il n'est plus visible sur la page, indique à l'analyseur que la page a fini de se charger et que le scan peut continuer. Ne peut pas être utilisé avec `DAST_PAGE_IS_READY_ELEMENT`. |
| `DAST_PAGE_IS_READY_ELEMENT` | [sélecteur](authentication.md#finding-an-elements-selector) | `css:#page-is-ready` | Sélecteur qui, lorsqu'il est détecté comme visible sur la page, indique à l'analyseur que la page a fini de se charger et que le scan peut continuer. Ne peut pas être utilisé avec `DAST_PAGE_IS_LOADING_ELEMENT`. |
| `DAST_PAGE_MAX_RESPONSE_SIZE_MB` | nombre | `15` | La taille maximale du corps d'une réponse HTTP. Les réponses dont le corps dépasse cette taille sont bloquées par le navigateur. Par défaut : `10` Mo. |
| `DAST_PAGE_READY_AFTER_ACTION_TIMEOUT` | [Chaîne de durée](https://pkg.go.dev/time#ParseDuration) | `7s` | La durée maximale d'attente pour qu'un navigateur considère une page comme chargée et prête à être analysée. Par défaut : `7s`. |
| `DAST_PAGE_READY_AFTER_NAVIGATION_TIMEOUT` | [Chaîne de durée](https://pkg.go.dev/time#ParseDuration) | `15s` | La durée maximale d'attente pour qu'un navigateur navigue d'une page à une autre. Par défaut : `15s`. |
| `DAST_PASSIVE_SCAN_WORKER_COUNT` | int | `5` | Nombre de workers effectuant le scan passif en parallèle. Par défaut : le nombre de processeurs disponibles. |
| `DAST_PKCS12_CERTIFICATE_BASE64` | chaîne | `ZGZkZ2p5NGd...` | Le certificat PKCS12 utilisé pour les sites nécessitant le protocole Mutual TLS. Doit être encodé en texte base64. |
| `DAST_PKCS12_PASSWORD` | chaîne | `password` | Le mot de passe du certificat utilisé dans `DAST_PKCS12_CERTIFICATE_BASE64`. Créez des [variables CI/CD personnalisées](../../../../../ci/variables/_index.md#define-a-cicd-variable-in-the-ui) sensibles à l'aide de l'interface GitLab. |
| `DAST_REQUEST_ADVERTISE_SCAN` | booléen | `true` | Définissez sur `true` pour ajouter un en-tête `Via: GitLab DAST <version>` à chaque requête envoyée, indiquant que la requête a été envoyée dans le cadre d'un scan DAST GitLab. Par défaut : `false`. |
| `DAST_REQUEST_COOKIES` | dictionnaire | `abtesting_group:3,region:locked` | Un nom et une valeur de cookie à ajouter à chaque requête. |
| `DAST_REQUEST_HEADERS` | Chaîne | `Cache-control:no-cache` | Définissez une liste séparée par des virgules de noms et valeurs d'en-têtes de requête. Les en-têtes suivants ne sont pas pris en charge : `content-length`, `cookie2`, `keep-alive`, `hosts`, `trailer`, `transfer-encoding`, et tous les en-têtes avec le préfixe `proxy-`. |
| `DAST_REQUEST_USER_AGENT` | Chaîne |  | Définissez cette option pour modifier la chaîne user-agent envoyée par le navigateur. Le user-agent par défaut est Google Chrome sur Linux. |
| `DAST_SCOPE_ALLOW_HOSTS` | Liste de chaînes | `site.com,another.com` | Les noms d'hôte inclus dans cette variable sont considérés comme étant dans la portée lors du crawl. Par défaut, le nom d'hôte `DAST_TARGET_URL` est inclus dans la liste des hôtes autorisés. Les en-têtes définis à l'aide de `DAST_REQUEST_HEADERS` sont ajoutés à chaque requête envoyée à ces noms d'hôte. |
| `DAST_SCOPE_EXCLUDE_ELEMENTS` | [sélecteur](authentication.md#finding-an-elements-selector) | `a[href='2.html'],css:.no-follow` | Liste séparée par des virgules de sélecteurs ignorés lors du scan. |
| `DAST_SCOPE_EXCLUDE_HOSTS` | Liste de chaînes | `site.com,another.com` | Les noms d'hôte inclus dans cette variable sont considérés comme exclus et les connexions sont abandonnées de force. |
| `DAST_SCOPE_IGNORE_HOSTS` | Liste de chaînes | `site.com,another.com` | Les noms d'hôte inclus dans cette variable sont accessibles, mais ne sont pas attaqués et ne font pas l'objet de rapports. |
| `DAST_TARGET_CHECK_SKIP` | booléen | `true` | Définissez sur `true` pour empêcher DAST de vérifier que la cible est disponible avant le scan. Par défaut : `false`. |
| `DAST_TARGET_CHECK_TIMEOUT` | nombre | `60` | Délai limite en secondes pour attendre la disponibilité de la cible. Par défaut : `60s`. |
| `DAST_TARGET_PATHS_FILE` | chaîne | `/builds/project/urls.txt` | Scannez uniquement ces chemins au lieu de crawler l'ensemble du site. Définissez un chemin de fichier contenant une liste de chemins d'URL relatifs à `DAST_TARGET_URL`. Le fichier doit être en texte brut avec un chemin par ligne. Lorsque cette option est définie, `DAST_CRAWL_MAX_DEPTH` prend la valeur 1 par défaut. Pour éviter cela, définissez `DAST_OVERRIDE_MAX_DEPTH: false`. |
| `DAST_TARGET_PATHS` | chaîne | `/page1.html,/category1/page3.html` | Scannez uniquement ces chemins au lieu de crawler l'ensemble du site. Définissez une liste séparée par des virgules de chemins d'URL relatifs à `DAST_TARGET_URL`. Lorsque cette option est définie, `DAST_CRAWL_MAX_DEPTH` prend la valeur 1 par défaut. Pour éviter cela, définissez `DAST_OVERRIDE_MAX_DEPTH: false`. |
| `DAST_TARGET_URL` | URL | `https://site.com` | L'URL du site web à scanner. |
| `DAST_USE_CACHE` | booléen | `true` | Définissez sur `false` pour désactiver la mise en cache. Par défaut : `true`. **Remarque** : la désactivation de la mise en cache peut provoquer des événements OOM ou des délais d'expiration des jobs DAST. |
| `DAST_CRAWL_GROUPED_URLS` | chaîne | `https://example.com/hello/*,https://example.com/world/*/details` | (Expérimental) Définissez une liste séparée par des virgules de modèles d'URL avec caractères génériques comportant au moins un `*`. Pour réduire le temps de scan, le scanner regroupe et analyse uniquement une URL correspondante par modèle. |

### Authentification {#authentication}

Ces variables indiquent au scanner comment s'authentifier auprès de votre application.

| Variable CI/CD | Type | Exemple | Description |
| :------------- | :--- | ------- | :---------- |
| `DAST_AUTH_AFTER_LOGIN_ACTIONS` | chaîne | `select(option=id:accept-yes),click(on=css:.continue)` | Liste séparée par des virgules d'actions à effectuer après la connexion mais avant la vérification de la connexion. Prend en charge les actions `click` et `select`. Voir [Effectuer des actions supplémentaires après la soumission du formulaire de connexion](authentication.md#taking-additional-actions-after-submitting-the-login-form). |
| `DAST_AUTH_BEFORE_LOGIN_ACTIONS` | [sélecteur](authentication.md#finding-an-elements-selector) | `css:.user,id:show-login-form` | Liste séparée par des virgules de sélecteurs représentant les éléments sur lesquels cliquer avant de saisir DAST_AUTH_USERNAME et DAST_AUTH_PASSWORD dans le formulaire de connexion. |
| `DAST_AUTH_CLEAR_INPUT_FIELDS` | booléen | `true` | Désactive l'effacement des champs nom d'utilisateur et mot de passe avant de tenter une connexion manuelle. Défini sur false par défaut. |
| `DAST_AUTH_COOKIE_NAMES` | chaîne | `sessionID,groupName` | Définissez une liste séparée par des virgules de noms de cookies pour spécifier les cookies utilisés pour l'authentification. |
| `DAST_AUTH_FIRST_SUBMIT_FIELD` | [sélecteur](authentication.md#finding-an-elements-selector) | `css:input[type=submit]` | Sélecteur décrivant l'élément sur lequel cliquer pour soumettre le formulaire de nom d'utilisateur dans le cadre d'un processus de connexion multi-pages. |
| `DAST_AUTH_NEGOTIATE_DELEGATION` | chaîne | `*.example.com,example.com,*.EXAMPLE.COM,EXAMPLE.COM` | Les serveurs devant être autorisés pour l'authentification intégrée et la délégation. Cette propriété définit deux politiques Chromium : [AuthServerAllowlist](https://chromeenterprise.google/policies/#AuthServerAllowlist) et [AuthNegotiateDelegateAllowlist](https://chromeenterprise.google/policies/#AuthNegotiateDelegateAllowlist). [Introduction](https://gitlab.com/gitlab-org/gitlab/-/issues/502476) dans GitLab 17.6. |
| `DAST_AUTH_OTP_FIELD` | [sélecteur](authentication.md#finding-an-elements-selector) | `name:otp` | Sélecteur décrivant l'élément utilisé pour saisir le mot de passe à usage unique sur le formulaire de connexion. |
| `DAST_AUTH_OTP_KEY` | Chaîne | `I5UXITDBMIQEIQKTKQFA====` | La clé secrète encodée en Base32 à utiliser lors de la génération d'un mot de passe à usage unique pour s'authentifier sur le site web. |
| `DAST_AUTH_OTP_SUBMIT_FIELD` | [sélecteur](authentication.md#finding-an-elements-selector) | `css:input[type=submit]` | Sélecteur décrivant l'élément sur lequel cliquer pour soumettre le formulaire OTP lorsqu'il est distinct du formulaire de nom d'utilisateur. |
| `DAST_AUTH_PASSWORD` | Chaîne | `P@55w0rd!` | Le mot de passe pour s'authentifier sur le site web. |
| `DAST_AUTH_PASSWORD_FIELD` | [sélecteur](authentication.md#finding-an-elements-selector) | `name:password` | Sélecteur décrivant l'élément utilisé pour saisir le mot de passe sur le formulaire de connexion. |
| `DAST_AUTH_SUBMIT_FIELD` | [sélecteur](authentication.md#finding-an-elements-selector) | `css:input[type=submit]` | Sélecteur décrivant l'élément sur lequel cliquer pour soumettre le formulaire de connexion dans le cas d'un formulaire de connexion mono-page, ou le formulaire de mot de passe dans le cas d'un formulaire de connexion multi-pages. |
| `DAST_AUTH_SUCCESS_IF_AT_URL` | URL | `https://www.site.com/welcome*` | URL comparée à l'URL du navigateur pour déterminer si l'authentification a réussi après la soumission du formulaire de connexion. Le caractère générique `*` peut être utilisé pour correspondre à une URL dynamique. |
| `DAST_AUTH_SUCCESS_IF_ELEMENT_FOUND` | [sélecteur](authentication.md#finding-an-elements-selector) | `css:.user-avatar` | Sélecteur décrivant un élément dont la présence est utilisée pour déterminer si l'authentification a réussi après la soumission du formulaire de connexion. |
| `DAST_AUTH_SUCCESS_IF_NO_LOGIN_FORM` | booléen | `true` | Vérifie la réussite de l'authentification en vérifiant l'absence d'un formulaire de connexion après la soumission du formulaire de connexion. Cette vérification de réussite est activée par défaut. |
| `DAST_AUTH_TYPE` | chaîne | `basic-digest` | Le type d'authentification à utiliser. |
| `DAST_AUTH_URL` | URL | `https://www.site.com/login` | L'URL de la page contenant le formulaire de connexion sur le site web cible. DAST_AUTH_USERNAME et DAST_AUTH_PASSWORD sont soumis avec le formulaire de connexion pour créer un scan authentifié. |
| `DAST_AUTH_USERNAME` | chaîne | `user@email.com` | Le nom d'utilisateur pour s'authentifier sur le site web. |
| `DAST_AUTH_USERNAME_FIELD` | [sélecteur](authentication.md#finding-an-elements-selector) | `name:username` | Sélecteur décrivant l'élément utilisé pour saisir le nom d'utilisateur sur le formulaire de connexion. |
| `DAST_SCOPE_EXCLUDE_URLS` | URLs | `https://site.com/.*/sign-out` | Les URL à ignorer pendant le scan authentifié ; séparées par des virgules. La syntaxe des expressions régulières peut être utilisée pour correspondre à plusieurs URL. Par exemple, `.*` correspond à une séquence de caractères arbitraire. |
| `DAST_AUTH_REPORT` | booléen | `true` | Définissez sur `true` pour générer un rapport détaillant les étapes effectuées pendant le processus d'authentification. Vous devez également définir `gl-dast-debug-auth-report.html` comme artefact de job CI pour pouvoir accéder au rapport généré. Le contenu du rapport facilite le débogage des échecs d'authentification. Par défaut : `false`. |
