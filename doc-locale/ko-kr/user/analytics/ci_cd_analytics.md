CI/CD 분석을 사용하여 파이프라인 성능과 성공율에 대한 인사이트를 얻습니다.

CI/CD 분석 페이지는 GitLab UI에서 직접 중요한 CI/CD 파이프라인 메트릭에 대한 시각화를 제공합니다. 이러한 시각화는 개발 팀이 소프트웨어 개발 프로세스의 상태와 효율성을 빠르게 이해하는 데 도움이 됩니다.

## CI/CD 분석 보기 {#view-cicd-analytics}

{{< history >}}

- [업데이트됨](https://gitlab.com/gitlab-org/gitlab/-/issues/353607) GitLab 18.0에서 사용 가능한 경우 ClickHouse를 데이터 소스로 사용하여 분석을 개선했습니다.

{{< /history >}}

CI/CD 분석을 보려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **분석** > **CI/CD 분석**을 선택합니다.

## 파이프라인 메트릭 {#pipeline-metrics}

파이프라인 성공 및 실패의 기록과 각 파이프라인이 실행된 기간을 볼 수 있습니다. 파이프라인 통계는 상태에 관계없이 프로젝트의 모든 사용 가능한 파이프라인을 수집하여 수집됩니다. 각 개별 날짜에 사용 가능한 데이터는 파이프라인이 시작된 시간을 기반으로 합니다.

CI/CD 분석은 파이프라인에 대한 주요 메트릭을 표시합니다:

- **파이프라인 실행 합계**: 선택한 시간 기간에 실행된 파이프라인의 총 개수입니다. 총 파이프라인 계산에는 자식 파이프라인과 잘못된 YAML로 실패한 파이프라인이 포함됩니다. 다른 특성을 기반으로 파이프라인을 필터링하려면 [Pipelines API](../../api/pipelines.md#list-project-pipelines)를 사용합니다.
- **기간 중간값**: 파이프라인이 완료되는 데 걸리는 중앙값 시간입니다.
- **실패율**: 실패한 파이프라인의 백분율입니다.
- **성공율**: 성공적으로 완료된 파이프라인의 백분율입니다.
- **Other rate**: 건너뛰거나 취소된 파이프라인의 백분율입니다.

## 결과 필터링 {#filter-your-results}

분석 데이터를 필터링하여 특정 영역에 집중할 수 있습니다:

- **소스**: 파이프라인 트리거 소스로 필터링합니다.
- **Branch (브랜치)**: 파이프라인이 실행된 브랜치로 필터링합니다.
- **날짜 범위**: 분석할 시간 기간을 선택합니다(예: 지난주).

필터링을 통해 특정 워크플로우 구성 요소의 성능을 분석하거나 다른 브랜치를 비교할 수 있습니다.

## 파이프라인 기간 차트 {#pipeline-duration-chart}

기간 차트는 시간에 따라 파이프라인 실행 시간이 어떻게 변했는지 보여줍니다. 차트에 표시되는 항목:

- **중앙값 (상위 50%)**: 일반적인 파이프라인 기간입니다.
- **상위 95%**: 파이프라인의 95%가 이 시간 이내에 완료되며, 5%만 더 오래 걸립니다.

이 시각화는 파이프라인 기간의 추세를 식별하는 데 도움이 되므로 시간에 따른 CI/CD 프로세스 효율성을 파악할 수 있습니다.

## 파이프라인 상태 차트 {#pipeline-status-chart}

상태 차트는 시간에 따른 파이프라인 상태 분포를 보여줍니다:

- **성공**: 오류 없이 완료된 파이프라인입니다.
- **실패함**: 오류로 인해 성공적으로 완료되지 않은 파이프라인입니다.
- **기타**: 다른 상태(취소됨, 건너뜀)의 파이프라인입니다.

이 시각화는 파이프라인의 안정성을 추적하고 높은 실패율의 기간을 식별하는 데 도움이 됩니다.

## CI/CD 작업 성능 메트릭 {#cicd-job-performance-metrics}

{{< details >}}

- 티어:  Premium, Ultimate
- 제공 서비스: GitLab.com
- 상태:  제한적 출시

{{< /details >}}

{{< history >}}

- [도입됨](https://gitlab.com/groups/gitlab-org/-/work_items/18548) GitLab 18.9에서 제한적 출시로 제공됩니다.

{{< /history >}}

> [!note]
> GitLab Self-Managed 또는 GitLab Dedicated에서는 기본적으로 사용할 수 없습니다. GitLab Self-Managed 및 GitLab Dedicated 인스턴스에서 CI/CD 작업 성능 메트릭을 보려면 [ClickHouse](../../integration/clickhouse.md)를 구성해야 합니다.

CI/CD 작업 성능 추세를 통해 개발자는 비효율적이거나 문제가 있는 CI/CD 작업을 빠르게 식별할 수 있습니다. 이러한 기능을 GitLab UI에 직접 포함하면 개발자는 CI/CD 성능 문제를 파악하고 수정할 수 있는 컨텍스트를 제공합니다

작업 성능 메트릭을 통해 병목 지점을 식별하고, 작업 안정성을 모니터링하며, 전체 파이프라인 기간에 가장 큰 영향을 미치는 작업에 최적화 노력을 집중할 수 있습니다.

작업 성능 섹션은 선택한 시간 기간의 파이프라인의 각 작업에 대한 메트릭을 표시합니다:

- **작업 이름**: CI/CD 작업의 이름입니다.
- **P50 duration** (중앙값): 이 작업의 일반적인 실행 시간입니다. 작업 실행의 절반은 더 빨리 완료되고 절반은 더 오래 걸립니다.
- **P95 기간**: 작업 실행의 95%가 이 시간 이내에 완료됩니다. 이 메트릭을 사용하여 이상 및 최악의 시나리오를 식별합니다.
- **실패율**: 실패한 작업 실행의 백분율입니다. 높은 비율은 안정성 문제를 나타내며 조사가 필요합니다.

기본적으로 표는 평균 기간으로 정렬됩니다(가장 오래 실행되는 작업이 먼저). 표는 페이지당 10개의 작업을 페이지 매김 컨트롤과 함께 표시합니다. 열 헤더를 선택하여 해당 메트릭으로 정렬하거나 검색 표시줄을 사용하여 이름으로 특정 작업을 찾을 수 있습니다.
