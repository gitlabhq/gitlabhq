GitLab의 작업은 이슈 내에서 생성할 수 있는 계획 항목입니다. [이슈](project/issues/_index.md)에 캡처된 사용자 스토리를 작업으로 더 작은 추적 가능한 항목으로 분류합니다.

이슈를 계획할 때 기술적 요구 사항 또는 완료하는 데 필요한 단계를 캡처하고 분류하는 방법이 필요합니다. 관련 작업이 있는 이슈는 더 잘 정의되어 있으므로 더 정확한 이슈 가중치와 완료 기준을 제공할 수 있습니다.

최신 업데이트는 [작업 로드맵](https://gitlab.com/groups/gitlab-org/-/epics/7103)을 확인하세요.

작업은 작업 항목의 한 유형이며 GitLab의 [기본 이슈 유형](https://gitlab.com/gitlab-org/gitlab/-/issues/323404)을 향한 단계입니다. 이슈 및 [에픽](group/epics/_index.md)을 작업 항목으로 마이그레이션하고 사용자 정의 작업 항목 유형을 추가하는 로드맵은 [에픽 6033](https://gitlab.com/groups/gitlab-org/-/work_items/6033)을 참조하세요.

## 작업 보기 {#view-tasks}

이슈의 **하위 항목** 섹션에서 작업을 봅니다.

[작업 항목 목록 필터링](work_items/_index.md#filter-work-items)을 할 수도 있으며 `Type = task`입니다.

이슈에서 또는 **작업 항목** 목록에서 작업을 선택하면 화면 오른쪽의 세부 정보 패널에서 열립니다. 더 작은 화면에서는 이 패널이 페이지와 겹칩니다.

전체 페이지 보기에서 작업을 열려면:

- 작업을 마우스 오른쪽 버튼으로 클릭하거나 <kbd>Command</kbd> 또는 <kbd>Control</kbd>을 누른 상태에서 선택하여 새 브라우저 탭에서 엽니다.
- 세부 정보 패널의 오른쪽 위 모서리에서 **전체 페이지로 열기** ({{< icon name="maximize" >}})를 선택합니다.

## 작업 생성 {#create-a-task}

{{< history >}}

- 작업이 생성되는 프로젝트를 선택하는 옵션이 GitLab 17.1에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/issues/436255)되었습니다.

{{< /history >}}

사전 요구 사항:

- 프로젝트의 게스트, 플래너, 리포터, 개발자, 유지 관리자 또는 소유자 역할을 가져야 하거나 프로젝트가 공개여야 합니다.

작업을 생성하려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **계획** > **작업 항목**을 선택합니다.
1. 오른쪽 위 모서리에서 **새 항목**을 선택합니다.
1. **유형** 드롭다운 목록에서 이미 선택되어 있지 않으면 **작업**을 선택합니다.
1. 다음을 완료합니다:
   - 작업 제목을 입력합니다.
   - 작업 설명을 입력합니다.
   - 선택 사항입니다. 대화 상자 사이드바에서 새 작업에 대한 **상위** [프로젝트](project/organize_work_with_projects.md)를 선택합니다.
1. **작업 생성**을 선택합니다.

### 작업 목록 항목에서 {#from-a-task-list-item}

사전 요구 사항:

- 프로젝트의 게스트, 플래너, 리포터, 개발자, 유지 관리자 또는 소유자 역할을 가져야 합니다.

이슈 설명의 작업 목록 항목을 작업으로 변환하려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **계획** > **작업 항목**을 선택한 다음 **유형** = **이슈**로 필터링하고 이슈를 선택합니다.
1. 이슈 설명에서 작업 목록 항목 위에 마우스를 올리고 옵션 메뉴({{< icon name="ellipsis_v" >}})를 선택합니다.
1. **하위 항목으로 변환**을 선택합니다.
1. 선택 사항입니다. 작업 제목을 편집하고 설명을 추가합니다.
1. **작업 생성**을 선택합니다.

작업 목록 항목이 이슈 설명에서 제거되고 **하위 항목** 섹션에 추가됩니다. 중첩된 작업 목록 항목이 중첩 수준을 올려서 이동합니다.

## 이슈에 기존 작업 추가 {#add-existing-tasks-to-an-issue}

사전 요구 사항:

- 프로젝트의 게스트, 플래너, 리포터, 개발자, 유지 관리자 또는 소유자 역할을 가져야 하거나 프로젝트가 공개여야 합니다.

이슈에 기존 작업을 추가하려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **계획** > **작업 항목**을 선택한 다음 **유형** = **이슈**로 필터링하고 이슈를 선택합니다.
1. 이슈 설명의 **하위 항목** 섹션에서 **추가** ({{< icon name="plus" >}})를 선택합니다.
1. **기존 작업**을 선택합니다.
1. 제목으로 작업을 검색합니다.
1. 이슈에 추가할 작업을 하나 이상 선택합니다.
1. **작업 추가**를 선택합니다.

작업을 편집하려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **계획** > **작업 항목**을 선택한 다음 **유형** = **작업**으로 필터링하고 작업을 선택합니다.

작업의 설명을 편집하려면:

1. 변경을 수행하고 **저장**을 선택합니다.

작업을 이슈로 승격하려면:

## 작업을 다른 항목 유형으로 변환 {#convert-a-task-into-another-item-type}

{{< history >}}

- GitLab 17.8에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/issues/385131)되었으며 [기능 플래그](../administration/feature_flags/_index.md)라고 명명되어 `work_items_beta`입니다. 기본적으로 사용 중지됩니다.
- [이동](https://gitlab.com/gitlab-org/gitlab/-/issues/385131) [플래그](../administration/feature_flags/_index.md)로 명명되어 `okrs_mvc`입니다. 현재 플래그 상태는 이 페이지의 맨 위를 참조하세요.

{{< /history >}}

작업을 다음과 같은 다른 항목 유형으로 변환합니다:

- 이슈
- 목표
- 핵심 결과

> [!warning]
> 유형을 변경하면 대상 유형이 원본 유형의 모든 필드를 지원하지 않는 경우 데이터 손실이 발생할 수 있습니다.

사전 요구 사항:

- 변환하려는 작업에 상위 항목이 할당되어 있지 않아야 합니다.

작업을 다른 항목 유형으로 변환하려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **계획** > **작업 항목**을 선택한 다음 **유형** = **작업**으로 필터링하고 작업을 선택합니다.
1. 선택 사항입니다. 작업에 상위 이슈가 할당되어 있으면 제거합니다. 작업에 `/remove_parent` 빠른 작업을 포함한 댓글을 추가합니다.
1. 오른쪽 위 모서리에서 **추가 작업** ({{< icon name="ellipsis_v" >}})을 선택한 다음 **유형 변경**을 선택합니다.
1. 원하는 항목 유형을 선택합니다.
1. 모든 조건이 충족되면 **유형 변경**을 선택합니다.

또는 [`/type` 빠른 작업](project/quick_actions.md#type)을 사용하고 댓글에서 `issue`, `objective` 또는 `key result`이 뒤에 옵니다.

## 이슈에서 작업 제거 {#remove-a-task-from-an-issue}

{{< history >}}

- GitLab 17.0에서 최소 필수 역할이 리포터에서 게스트로 [변경](https://gitlab.com/gitlab-org/gitlab/-/issues/404799)되었습니다.

{{< /history >}}

사전 요구 사항:

- 프로젝트의 게스트, 플래너, 리포터, 개발자, 유지 관리자 또는 소유자 역할을 가져야 합니다.

작업을 삭제하지 않고 이슈에서 제거할 수 있습니다. 다시 연결하려면 [이슈를 상위로 설정](#set-an-issue-as-a-parent)을 참조하세요.

**하위 항목** 섹션을 사용하여 이슈에서 작업을 제거하려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **계획** > **작업 항목**을 선택한 다음 **유형** = **이슈**로 필터링하고 이슈를 선택합니다.
1. 이슈 설명의 **하위 항목** 섹션에서 제거하려는 작업 옆의 옵션 메뉴({{< icon name="ellipsis_v" >}})를 선택합니다.
1. **작업 제거**를 선택합니다.

작업 세부 정보 패널을 사용하여 이슈에서 작업을 제거하려면:

1. **계획** > **작업 항목**을 선택한 다음 **유형** = **작업**으로 필터링하고 작업을 선택합니다.
1. 오른쪽 사이드바의 **상위** 옆에서 **편집**을 선택합니다.
1. 드롭다운 목록의 오른쪽 위 모서리에서 **지우기**를 선택합니다.

## 작업 삭제 {#delete-a-task}

{{< history >}}

- GitLab 17.7에서 최소 사용자 역할이 소유자에서 플래너로 [변경](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/169256)되었습니다.

{{< /history >}}

사전 요구 사항:

- 다음 중 하나를 수행해야 합니다:
  - 작업의 작성자이고 프로젝트의 게스트, 리포터, 개발자 또는 유지 관리자 역할을 가집니다.
  - 프로젝트의 플래너 또는 소유자 역할을 가집니다.

작업을 삭제하려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **계획** > **작업 항목**을 선택한 다음 **유형** = **작업**으로 필터링하고 작업을 선택합니다.
1. **추가 작업** ({{< icon name="ellipsis_v" >}})을 선택합니다.
1. **작업 삭제**를 선택합니다.
1. 확인 대화에서 **작업 삭제**를 선택합니다.

## 작업 순서 변경 {#reorder-tasks}

{{< history >}}

- GitLab 17.7에서 최소 사용자 역할이 리포터에서 플래너로 [변경](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/169256)되었습니다.

{{< /history >}}

사전 요구 사항:

- 프로젝트의 플래너, 리포터, 개발자, 유지 관리자 또는 소유자 역할을 가져야 합니다.

기본적으로 작업은 생성 날짜순으로 정렬됩니다. 이슈의 **하위 항목** 섹션에서 순서를 변경하려면 원하는 순서로 드래그합니다.

**작업 항목** 목록의 작업을 정렬하려면:

1. 필터 표시줄의 오른쪽에서 **만든 날짜** 드롭다운 목록을 선택합니다.
1. 정렬 기준을 선택합니다:

   - 우선 순위
   - 만든 날짜
   - 업데이트 날짜
   - 종료된 날짜
   - 마일스톤 마감일
   - 마감일
   - 인기도
   - 레이블 우선 순위
   - 수동(항목을 선호하는 순서로 드래그합니다. 정렬 방향은 무시됨)
   - 제목
   - 시작일

1. 오름차순과 내림차순을 전환하려면 **정렬 순서** ({{< icon name="sort-lowest" >}} 또는 {{< icon name="sort-highest" >}})를 선택합니다.

## 작업 이메일 주소 복사 {#copy-task-email-address}

이메일을 보내어 작업에서 댓글을 생성할 수 있습니다. 이 주소로 이메일을 보내면 이메일 본문을 포함하는 댓글이 생성됩니다.

이메일로 댓글을 생성하고 필요한 구성에 대한 자세한 내용은 [이메일을 보내 댓글에 답글 달기](discussions/_index.md#reply-to-a-comment-by-sending-email)를 참조하세요.

작업의 이메일 주소를 복사하려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **계획** > **작업 항목**을 선택한 다음 **유형** = **작업**으로 필터링하고 작업을 선택합니다.
1. 오른쪽 위 모서리에서 **추가 작업** ({{< icon name="ellipsis_v" >}})을 선택한 다음 **작업 이메일 주소 복사**를 선택합니다.

## 이슈를 상위로 설정 {#set-an-issue-as-a-parent}

사전 요구 사항:

- 프로젝트의 게스트, 플래너, 리포터, 개발자, 유지 관리자 또는 소유자 역할을 가져야 합니다.
- 이슈와 작업이 같은 프로젝트에 속해야 합니다.

이슈를 작업의 상위로 설정하려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **계획** > **작업 항목**을 선택한 다음 **유형** = **작업**으로 필터링하고 작업을 선택합니다.
1. 오른쪽 사이드바의 **상위** 섹션에서 **편집**을 선택합니다.
1. 드롭다운 목록에서 추가할 상위를 선택합니다.
1. 드롭다운 목록 외부의 모든 영역을 선택합니다.

작업의 상위 항목을 제거하려면:

1. **상위** 섹션에서 **편집**을 선택합니다.
1. 드롭다운 목록의 오른쪽 위 모서리에서 **지우기**를 선택합니다.
1. 드롭다운 목록 외부의 모든 영역을 선택합니다.

## 참여자 {#participants}

참여자는 작업과 상호작용한 사용자입니다. 참여자 보기에 대한 정보는 [참여자](participants.md)를 참조하세요.

## 기밀 작업 {#confidential-tasks}

기밀 작업은 [충분한 권한](#who-can-see-confidential-tasks)을 가진 프로젝트 구성원에게만 표시되는 작업입니다. 기밀 작업을 사용하여 보안 취약점을 비공개로 유지하거나 서프라이즈가 유출되는 것을 방지할 수 있습니다.

### 작업을 기밀로 설정 {#make-a-task-confidential}

기본적으로 작업은 공개입니다. 작업을 생성하거나 편집할 때 작업을 기밀로 설정할 수 있습니다.

사전 요구 사항:

- 프로젝트의 리포터, 개발자, 유지 관리자 또는 소유자 역할을 가져야 합니다.
- 작업에 비공개가 아닌 상위 이슈가 있고 이슈를 비공개로 설정하려면 먼저 모든 하위 작업을 비공개로 설정해야 합니다. [기밀 이슈](project/issues/confidential_issues.md)는 기밀 하위 항목만 가질 수 있습니다.

#### 새로운 작업에서 {#in-a-new-task}

새 작업을 생성하면 텍스트 영역 바로 아래에 작업을 기밀로 표시하는 확인란을 사용할 수 있습니다.

해당 상자를 선택하고 **작업 생성**을 선택합니다.

#### 기존 작업에서 {#in-an-existing-task}

기존 작업의 기밀성을 변경하려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **계획** > **작업 항목**을 선택한 다음 **유형** = **작업**으로 필터링하고 작업을 선택합니다.
1. 오른쪽 위 모서리에서 세로 줄임표({{< icon name="ellipsis_v" >}})를 선택합니다.
1. **비공개 활성화**를 선택합니다.

### 기밀 작업을 볼 수 있는 사람 {#who-can-see-confidential-tasks}

작업이 기밀로 설정되면 프로젝트의 리포터, 개발자, 유지 관리자 또는 소유자 역할을 가진 사용자만 액세스할 수 있습니다. 게스트 또는 [최소](permissions.md#users-with-minimal-access) 역할을 가진 사용자는 이전에 참여했더라도 작업에 액세스할 수 없습니다.

게스트 역할을 가진 사용자는 기밀 작업을 생성할 수 있지만 자신이 생성한 작업만 볼 수 있습니다.

게스트 역할 또는 비구성원인 사용자는 할당된 경우 기밀 작업을 볼 수 있습니다. 게스트 사용자 또는 비구성원이 기밀 작업에서 할당 해제되면 더 이상 볼 수 없습니다.

기밀 작업은 필요한 권한이 없는 사용자의 검색 결과에서 숨겨집니다.

### 기밀 작업 표시기 {#confidential-task-indicators}

기밀 작업은 일반 작업과 몇 가지 방식으로 시각적으로 다릅니다. 작업이 나열된 곳 어디든지 기밀({{< icon name="eye-slash" >}}) 아이콘을 기밀로 표시된 작업 옆에서 볼 수 있습니다.

[충분한 권한](#who-can-see-confidential-tasks)이 없으면 기밀 작업을 볼 수 없습니다.

마찬가지로 작업 내부에서 기밀({{< icon name="eye-slash" >}}) 아이콘을 이동 경로 바로 옆에서 볼 수 있습니다.

정규에서 기밀로 또는 그 반대로의 모든 변경은 작업의 댓글에서 시스템 노트로 표시됩니다. 예를 들면:

- {{< icon name="eye-slash" >}} Jo Garcia가 5분 전 이슈를 기밀로 설정했습니다.
- {{< icon name="eye" >}} Jo Garcia가 방금 이슈를 모두에게 공개했습니다.

## 토론 잠금 {#lock-discussion}

{{< history >}}

- GitLab 16.9에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/issues/398649)되었으며 [기능 플래그](../administration/feature_flags/_index.md)라고 명명되어 `work_items_beta`입니다. 기본적으로 사용 중지됩니다.
- 기능 플래그 `work_items_beta`이 GitLab 18.6에서 [제거](https://gitlab.com/gitlab-com/gl-infra/production/-/issues/17549)되었습니다.

{{< /history >}}

작업에서 공개 댓글을 방지할 수 있습니다. 그렇게 하면 프로젝트 구성원만 댓글을 추가하고 편집할 수 있습니다.

사전 요구 사항:

- 리포터, 개발자, 유지 관리자 또는 소유자 역할을 가져야 합니다.

작업을 잠그려면:

1. 오른쪽 위 모서리에서 세로 줄임표({{< icon name="ellipsis_v" >}})를 선택합니다.
1. **토론 잠금**을 선택합니다.

시스템 노트가 페이지 세부 정보에 추가됩니다.

토론이 잠긴 상태로 작업을 종료하면 토론이 잠금 해제될 때까지 다시 열 수 없습니다.

## 작업의 연결된 항목 {#linked-items-in-tasks}

{{< history >}}

- GitLab 17.0에서 [일반적으로 사용 가능](https://gitlab.com/gitlab-org/gitlab/-/merge_requests/150148)합니다. 기능 플래그 `linked_work_items`이 제거되었습니다.
- GitLab 17.0에서 최소 필수 역할이 리포터(참인 경우)에서 게스트로 [변경](https://gitlab.com/groups/gitlab-org/-/work_items/10267)되었습니다.

{{< /history >}}

연결된 항목은 양방향 관계이며 이모지 반응 섹션 아래 블록에 표시됩니다. 같은 프로젝트의 목표, 핵심 결과 또는 작업을 서로 연결할 수 있습니다.

사용자가 두 항목을 볼 수 있는 경우에만 관계가 UI에 나타납니다.

### 연결된 항목 추가 {#add-a-linked-item}

사전 요구 사항:

- 프로젝트의 게스트, 플래너, 리포터, 개발자, 유지 관리자 또는 소유자 역할을 가져야 합니다.

항목을 작업에 연결하려면:

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **계획** > **작업 항목**을 선택한 다음 **유형** = **작업**으로 필터링하고 작업을 선택합니다.
1. 작업의 **링크된 항목** 섹션에서 **추가** ({{< icon name="plus" >}})를 선택합니다.
1. 두 항목 사이의 관계를 선택합니다. 다음 중 하나를 선택합니다.
   - **다음과 관련됨**
   - **차단**
   - **다음에 의해 차단됨**
1. 항목의 검색 텍스트, URL 또는 참조 ID를 입력합니다.
1. 연결할 모든 항목을 추가한 경우 검색 상자 아래에서 **추가**를 선택합니다.

모든 연결된 항목 추가를 완료한 경우 분류된 항목을 보아 관계를 시각적으로 더 잘 이해할 수 있습니다.

![연결된 항목 섹션에서 차단, 차단됨 및 다음과 관련됨으로 그룹화된 연결된 작업 항목.](img/linked_items_list_v16_5.png)

### 연결된 항목 제거 {#remove-a-linked-item}

사전 요구 사항:

- 프로젝트의 게스트, 플래너, 리포터, 개발자, 유지 관리자 또는 소유자 역할을 가져야 합니다.

1. 상단 바에서 **검색 또는 이동**을 선택하고 프로젝트를 찾습니다.
1. 왼쪽 사이드바에서 **계획** > **작업 항목**을 선택한 다음 **유형** = **작업**으로 필터링하고 작업을 선택합니다.
1. 작업의 **링크된 항목** 섹션에서 각 항목 옆의 세로 줄임표({{< icon name="ellipsis_v" >}})를 선택한 다음 **삭제**를 선택합니다.

양방향 관계 때문에 관계가 더 이상 항목 중 하나에도 나타나지 않습니다.

### 머지 리퀘스트 추가 및 작업 자동 종료 {#add-a-merge-request-and-automatically-close-tasks}

{{< history >}}

- GitLab 17.3에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/issues/440851)되었습니다.

{{< /history >}}

머지 리퀘스트가 병합되면 작업이 종료되도록 설정할 수 있습니다.

사전 요구 사항:

- 머지 리퀘스트를 포함하는 프로젝트에 대해 개발자, 유지 관리자 또는 소유자 역할을 가져야 합니다.
- 작업을 포함하는 프로젝트에 대해 리포터, 개발자, 유지 관리자 또는 소유자 역할을 가져야 합니다.

1. 머지 리퀘스트를 편집합니다.
1. **설명** 텍스트 상자에서 작업을 찾아 추가합니다.
   - 머지 리퀘스트를 이슈에 추가하는 데 사용하는 [종료 패턴](project/issues/managing_issues.md#closing-issues-automatically)을 사용합니다.
   - 작업이 머지 리퀘스트와 같은 프로젝트에 있으면 <kbd>#</kbd>을 입력한 다음 작업의 ID 또는 제목으로 작업을 검색할 수 있습니다.
   - 작업이 다른 프로젝트에 있으면 작업이 열려 있는 경우 브라우저에서 URL을 복사하거나 오른쪽 위 모서리에서 세로 줄임표({{< icon name="ellipsis_v" >}})를 선택하고 **참조 복사**를 선택하여 작업의 참조를 복사합니다.

머지 리퀘스트는 이제 본문에서 **개발** 섹션에 표시됩니다.

정확한 종료 패턴을 사용하여 머지 리퀘스트를 작업에 추가합니다.

[자동 이슈 종료](project/issues/managing_issues.md#disable-automatic-issue-closing)가 프로젝트 설정에서 켜져 있으면 다음 중 하나인 경우 작업이 자동으로 종료됩니다:

- 추가된 머지 리퀘스트가 병합됩니다.
- 종료 패턴으로 작업을 참조하는 커밋이 프로젝트의 기본 브랜치에 커밋됩니다.
