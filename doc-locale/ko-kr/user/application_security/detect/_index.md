소프트웨어 개발 수명 주기 전반에서 프로젝트의 리포지토리와 애플리케이션의 동작에서 취약성을 탐지합니다.

개발 중 취약성 위험을 관리하는 데 도움을 주기 위해:

- 코드 변경 사항을 브랜치로 푸시할 때 보안 스캐너가 실행됩니다.
- 브랜치에서 탐지된 취약성의 세부 사항을 볼 수 있습니다. 개발자는 이 시점에서 취약성을 수정하여 프로덕션 환경에 도달하기 전에 해결할 수 있습니다.
- 선택적으로, [취약성을 포함하는 머지 리퀘스트](../../project/merge_requests/widgets.md#application-security-scanning)에 추가 승인을 적용할 수 있습니다. 자세한 내용은 [머지 리퀘스트 승인 정책](../policies/merge_request_approval_policies.md)을 참조하세요.

개발 외부에서 취약성을 관리하는 데 도움을 주기 위해:

- 보안 검사를 예약하거나 수동으로 실행할 수 있습니다.
- 기본 브랜치에서 탐지된 취약성은 [취약성 보고서](../vulnerability_report/_index.md)에 나타납니다. 이 보고서를 사용하여 취약성을 심사, 분석 및 수정합니다.

## 보안 검사 {#security-scanning}

보안 검사에서 최대의 이점을 얻으려면 다음을 이해하는 것이 중요합니다:

- 보안 검사를 트리거하는 방법입니다.
- 애플리케이션 또는 리포지토리의 어떤 측면을 검사하는지입니다.
- 어떤 스캐너가 실행되는지를 결정하는 것입니다.
- 보안 검사가 어떻게 발생하는지입니다.

### 트리거 {#triggers}

CI/CD 파이프라인의 보안 검사는 변경 사항이 프로젝트의 리포지토리로 푸시될 때 기본적으로 트리거됩니다.

다음과 같은 방법으로도 보안 검사를 실행할 수 있습니다:

- [CI/CD 파이프라인을 수동으로 실행](../../../ci/pipelines/_index.md#run-a-pipeline-manually)합니다.
- [검사 실행 정책](../policies/scan_execution_policies.md)을 사용하여 보안 검사를 예약합니다.
- DAST의 경우에만, [온디맨드 DAST 검사를 수동으로](../dast/on-demand_scan.md) 실행하거나 [일정에 따라](../../../ci/pipelines/schedules.md) 실행합니다.
- SAST의 경우에만, [GitLab for VS Code 확장](../../../editor_extensions/visual_studio_code/security_scanning.md#perform-sast-scanning)을 사용하여 검사를 실행합니다.

### 탐지 범위 {#detection-coverage}

프로젝트의 리포지토리를 검사하고 취약성을 위해 애플리케이션의 동작을 테스트합니다:

- 리포지토리 검사는 프로젝트의 리포지토리에서 취약성을 탐지할 수 있습니다. 범위에는 애플리케이션의 소스 코드, 애플리케이션이 종속된 라이브러리 및 컨테이너 이미지가 포함됩니다.
- 애플리케이션 및 API의 동작 테스트는 런타임에만 발생하는 취약성을 탐지할 수 있습니다.

#### 리포지토리 검사 {#repository-scanning}

프로젝트의 리포지토리는 소스 코드, 종속성 선언 및 인프라 정의를 포함할 수 있습니다. 리포지토리 검사는 이 각각의 항목에서 취약성을 탐지할 수 있습니다.

리포지토리 검사 도구는 다음을 포함합니다:

- 정적 애플리케이션 보안 테스트(SAST): 취약성을 위해 소스 코드를 분석합니다.
- 코드 기반 인프라(IaC) 검사: 애플리케이션의 인프라 정의에서 취약성을 탐지합니다.
- 시크릿 검색: 시크릿이 리포지토리로 커밋되는 것을 탐지하고 차단합니다.
- 종속성 검사: 애플리케이션의 종속성 및 컨테이너 이미지에서 취약성을 탐지합니다.

#### 동작 테스트 {#behavioral-testing}

동작 테스트는 알려진 취약성 및 예기치 않은 동작을 테스트하기 위해 배포 가능한 애플리케이션이 필요합니다.

동작 테스트 도구는 다음을 포함합니다:

- 동적 애플리케이션 보안 테스트(DAST): 알려진 공격 벡터를 위해 애플리케이션을 테스트합니다.
- API 보안 테스트: 알려진 공격 및 입력에 대한 취약성을 위해 애플리케이션의 API를 테스트합니다.
- 범위 기반 퍼즈 테스트: 예기치 않은 동작을 위해 애플리케이션을 테스트합니다.

### 스캐너 선택 {#scanner-selection}

보안 스캐너는 다음 중 하나의 방법으로 프로젝트에 대해 활성화됩니다:

- 스캐너의 CI/CD 템플릿을 `.gitlab-ci.yml` 파일에 추가하거나, 직접 추가하거나 [AutoDevOps](../../../topics/autodevops/_index.md)를 사용하여 추가합니다.
- 검사 실행 정책, 파이프라인 실행 정책 또는 [규정 준수 프레임워크](../../compliance/compliance_frameworks/_index.md)를 사용하여 스캐너를 적용합니다. 이 적용은 프로젝트에 직접 적용되거나 프로젝트의 상위 그룹에서 상속될 수 있습니다.

자세한 내용은 [보안 구성](security_configuration.md)을 참조하세요.

### 보안 검사 프로세스 {#security-scanning-process}

보안 검사 프로세스는 다음과 같습니다:

1. CI/CD 작업 기준에 따라, 활성화되고 파이프라인에서 실행할 의도가 있는 스캐너는 별도의 작업으로 실행됩니다.

   각 성공적인 작업은 작업 아티팩트로 하나 이상의 보안 보고서를 출력합니다. 이 보고서는 이전에 발견되었는지, 무시되었는지 또는 새로운 것인지와 관계없이 브랜치에서 탐지된 모든 취약성의 세부 사항을 포함합니다.
1. 각 보안 보고서는 [유효성 검증](security_report_validation.md) 및 [중복 제거](vulnerability_deduplication.md)를 포함하여 처리됩니다.
1. 모든 작업이 완료되면(수동 작업 포함), 결과를 다운로드하거나 볼 수 있습니다.

보안 검사 출력에 대한 자세한 내용은 [보안 검사 결과](security_scanning_results.md)를 참조하세요.

#### CI/CD 보안 작업 기준 {#cicd-security-job-criteria}

CI/CD 파이프라인의 보안 검사 작업은 다음 기준에 의해 결정됩니다:

1. 보안 검사 템플릿 포함

   보안 검사 작업의 선택은 먼저 정책 또는 규정 준수 프레임워크에 의해 포함되거나 적용되는 템플릿에 의해 결정됩니다.

   보안 검사는 브랜치 파이프라인에서 기본적으로 실행됩니다. 머지 리퀘스트 파이프라인에서 보안 검사를 실행하려면 [이를 활성화](security_configuration.md#use-security-scanning-tools-with-merge-request-pipelines)해야 합니다.
1. 규칙의 평가

   각 템플릿에는 분석기가 실행되는지 여부를 결정하는 정의된 [규칙](../../../ci/yaml/_index.md#rules)이 있습니다.

   예를 들어, 일부 분석기는 특정 유형의 파일이 리포지토리에서 탐지될 때만 실행됩니다.
1. 분석기 로직

   템플릿의 규칙이 작업을 실행하도록 지정하면, 작업은 템플릿에서 지정한 파이프라인 스테이지에서 생성됩니다. 그러나 각 분석기는 분석기 자체가 실행되는지 여부를 결정하는 자체 로직을 가지고 있습니다.

   예를 들어, 종속성 검사가 기본 깊이에서 지원되는 파일을 탐지하지 않으면, 분석기는 실행되지 않고 아티팩트가 출력되지 않습니다.

작업은 취약성을 찾지 못하더라도 검사를 완료하면 통과합니다. 유일한 예외는 검사 범위 퍼즈 테스트이며, 발견 사항을 식별하면 실패합니다. 모든 작업은 전체 파이프라인을 실패하지 않도록 실패하도록 허용됩니다. 전체 파이프라인이 실패하기 때문에 작업 [`allow_failure` 설정](../../../ci/yaml/_index.md#allow_failure)을 변경하지 마세요.

## 데이터 개인정보 보호 {#data-privacy}

GitLab은 소스 코드를 처리하고 GitLab 러너에서 로컬로 분석을 수행합니다. GitLab 인프라(서버 및 러너) 외부로는 데이터가 전송되지 않습니다.

보안 분석기는 최신 서명, 규칙 및 패치 세트를 다운로드하기 위해서만 인터넷에 접근합니다. 스캐너가 인터넷에 접근하지 않으려면 [오프라인 환경](../offline_deployments/_index.md)을 사용하는 것을 고려하세요.
