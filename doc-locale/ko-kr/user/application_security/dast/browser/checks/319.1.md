## 설명 {#description}

대상 애플리케이션이 안전하지 않은 전송 프로토콜(HTTP)을 통해 리소스를 요청하는 것으로 확인되었습니다. 일반적으로 `http://` 스킴을 사용하여 리소스를 로드하는 HTML 요소 때문입니다. `https://`를 대신 사용해야 합니다. 대부분의 최신 브라우저가 이러한 요청을 자동으로 차단하므로 위험성은 제한적입니다.

이 파일들이 제대로 로드되지 않기 때문에 애플리케이션의 일부가 올바르게 작동하지 않을 수 있습니다.

## 수정 {#remediation}

URL(JavaScript, 스타일시트, 이미지, 비디오 및 기타 미디어)에서 리소스를 로드하는 모든 HTML 요소가 `http://` 스킴을 대신 `https://` 스킴을 사용하도록 설정되어야 합니다. 또는 개발자는 `//` 스킴을 사용할 수 있습니다. 이는 원본 페이지가 로드된 것과 동일한 프로토콜을 통해서만 리소스를 로드합니다.

`https://example.com` 웹사이트를 방문하는 브라우저가 `<script src="//example.com/cdn/bundle.js"></script>`를 사용하여 파일을 로드하면, `example.com/cdn/bundle.js` 파일이 HTTPS를 통해 로드되는지 확인합니다.
