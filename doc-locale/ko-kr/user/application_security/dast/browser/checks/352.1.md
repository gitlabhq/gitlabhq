## 설명 {#description}

애플리케이션이 보안 애플리케이션 토큰이나 `SameSite` 쿠키 지시문을 사용하여 사이트 간 요청 위조(CSRF)로부터 보호하지 못했습니다.

이 취약성은 공격자가 제3자 사이트에 링크 또는 양식을 만들고 인증된 사용자를 속여 이에 접속하도록 만들어 악용될 수 있습니다.

## 수정 {#remediation}

모든 세션 쿠키에 `SameSite=Strict` 속성을 포함하도록 설정하는 것을 고려하세요. 다만, 다른 매체에서 링크를 공유할 때 사용성에 영향을 미칠 수 있다는 점에 주의해야 합니다. RFC의 [Top level navigations](https://datatracker.ietf.org/doc/html/draft-ietf-httpbis-rfc6265bis-08#section-8.8.2) 섹션에 설명된 대로 2개 쿠키 기반 접근 방식을 취하는 것을 권장합니다.

애플리케이션이 일반적인 프레임워크를 사용 중인 경우, Anti-CSRF 보호가 내장되어 있지만 활성화되어야 할 수 있습니다. 자세한 내용은 애플리케이션 프레임워크 문서를 참조하세요.

이 두 가지 옵션이 모두 적용되지 않는 경우, **strongly** 제3자 라이브러리를 사용할 것을 권장합니다. 보안 Anti-CSRF 시스템을 구현하는 것은 상당한 투자이며 올바르게 수행하기 어렵습니다.
