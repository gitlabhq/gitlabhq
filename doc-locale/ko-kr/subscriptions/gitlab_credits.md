GitLab Credits는 사용 기반 청구를 위한 표준화된 소비 통화입니다. 크레딧은 [GitLab Duo Agent Platform](../user/duo_agent_platform/_index.md)에서 사용되며, 각 사용 작업은 일정량의 크레딧을 소비합니다.

[GitLab Duo Pro 및 Enterprise](subscription-add-ons.md#gitlab-duo-pro-and-enterprise)와 이에 연결된 [GitLab Duo 기능](../user/gitlab_duo/feature_summary.md)은 사용량 기반으로 청구되지 않으며 GitLab Credits를 소비하지 않습니다.

크레딧은 크레딧 배수 표에 나열된 대로 사용자가 사용하는 기능과 모델을 기반으로 계산됩니다. [일반 공개(GA)](../policy/development_stages_support.md#generally-available) 기능에 대해 요금이 청구됩니다. 일부 릴리스 전 기능도 사용료가 발생합니다. 요금이 적용되면 해당 기능의 설명서 페이지에서 이것을 명시합니다.

청구는 프로젝트 수준이 아닌 루트 네임스페이스 또는 최상위 그룹 수준에서 발생합니다. 크레딧 사용량은 기능을 사용하는 프로젝트에 관계없이 작업을 수행하는 주체에게 귀속됩니다. 주체는 실제 사용자이거나 사람이 아닌 주체(예: 서비스 계정 또는 자동화된 플로우를 실행하는 봇)일 수 있습니다.

루트 네임스페이스 또는 최상위 그룹의 모든 사용량은 청구 목적으로 통합됩니다.

GitLab은 크레딧을 얻는 세 가지 방법을 제공합니다.

- 포함된 크레딧
- 월별 약정 풀
- 온디맨드 크레딧

클릭 방식 데모를 보려면 [GitLab Credits](https://gitlab.navattic.com/credits-dashboard)를 참조하세요.

## 포함된 크레딧 {#included-credits}

포함된 크레딧은 Premium 또는 Ultimate 티어의 모든 사용자에게 할당됩니다. 이러한 크레딧은 개인에게 부여되며 사용자 간에 공유할 수 없습니다. 포함된 크레딧은 매월 초에 초기화됩니다. 사용하지 않은 크레딧은 다음 달로 이월되지 않습니다.

[커뮤니티 프로그램 구독](community_programs.md)에는 포함된 크레딧이 제공되지 않습니다.

사람이 아닌 주체에게는 포함된 크레딧이 제공되지 않습니다. 이들의 크레딧 소비는 월별 약정 풀 및 온디맨드 크레딧을 통해 네임스페이스 수준에서 청구되며, 크레딧 사용 순서는 실제 사용자와 동일하게 적용됩니다.

포함된 크레딧에 대한 자세한 내용은 [GitLab 프로모션 이용 약관](https://about.gitlab.com/pricing/terms/)을 참조하세요.

## 월별 약정 풀 {#monthly-commitment-pool}

월별 약정 풀은 구독 내 모든 사용자가 사용할 수 있는 공유 크레딧 풀입니다. 구독 내 모든 사용자는 포함된 크레딧을 모두 소진한 후 이 공유 풀에서 크레딧을 사용할 수 있습니다.

사용자의 하위 집합에 대해 풀을 예약하거나 특정 사용자, 그룹 또는 프로젝트로 사용량을 격리할 수 없습니다. 개별 사용자의 사용량을 제한하려면 사용량 상한을 사용합니다.

반복되는 연간 또는 여러 해 기간으로 월별 약정 풀을 구매할 수 있습니다. 해당 연도에 대해 구매한 크레딧 수를 12로 나눕니다.

예를 들어 월별 약정 풀로 1,000개 크레딧을 구매하면, 계약 기간 동안 매월 1,000개 크레딧을 사용할 수 있습니다.

사용자는 GitLab 계정 팀을 통해 언제든지 약정량을 늘릴 수 있습니다. 추가된 약정은 남은 계약 기간 동안 적용됩니다. 약정은 갱신 시점에만 줄일 수 있습니다.

기본 제공하는 티어별 할인이 적용된 크레딧 약정을 구매할 수 있습니다. 약정 요금은 계약 기간이 시작될 때 선불로 청구됩니다.

크레딧은 구매 즉시 사용할 수 있으며, 매월 1일에 초기화됩니다. 사용하지 않은 크레딧은 다음 달로 이월되지 않습니다.

> [!note]
> 월별 약정 풀을 구매할 경우, 온디맨드 크레딧 사용을 포함한 사용량 기반 청구 약관에 동의하게 됩니다. 약관에 동의한 이후 온디맨드 청구는 남은 구독 기간 및 이후의 셀프 서비스 갱신 시에도 활성 상태로 유지되며 해지할 수 없습니다.

## 온디맨드 크레딧 {#on-demand-credits}

온디맨드 크레딧은 포함된 모든 크레딧과 월별 약정 풀의 크레딧을 모두 소진한 이후에 발생한 사용량에 적용됩니다. 온디맨드 크레딧은 매월 청구됩니다.

온디맨드 크레딧은 사용한 크레딧당 1달러($1)의 정가로 소비됩니다.

사용량 기반 청구 약관에 동의한 후부터 온디맨드 크레딧을 사용할 수 있습니다. 월별 약정을 구매할 때 이러한 약관을 수락하거나 고객 포털의 GitLab Credits 대시보드에서 직접 수락할 수 있습니다. 사용량 기반 청구 약관을 수락하면, 현재 월별 청구 기간에 이미 누적된 모든 온디맨드 요금과 향후 발생하는 모든 온디맨드 요금을 지불하는 데 동의하는 것입니다.

사용량 기반 청구 약관을 수락하지 않으면, GitLab Duo Agent Platform을 사용할 수 없으며 온디맨드 크레딧을 소진할 수 없습니다. 월별 약정을 구매하거나 사용량 기반 청구 약관에 동의하면 GitLab Duo Agent Platform에 대한 액세스 권한을 다시 얻을 수 있습니다.

예를 들어, 구독에 매월 50개 크레딧의 월별 약정이 포함되어 있다고 가정합니다. 해당 월에 75개 크레딧이 사용된 경우, 처음 50개 크레딧은 월별 약정 풀에서 차감되고 추가된 25 크레딧은 온디맨드 사용량으로 청구됩니다.

## 사용 순서 {#usage-order}

GitLab Credits는 다음 순서로 차감됩니다.

1. 임시 평가 크레딧이 먼저 사용됩니다.
1. 포함된 크레딧은 공유 크레딧 전에 각 사용자가 소비합니다.
1. 크레딧의 월별 약정 풀은 포함된 모든 크레딧이 소비된 후에 사용됩니다.
1. 온디맨드 크레딧은 사용 가능한 다른 모든 크레딧(포함된 크레딧 및 월별 약정 풀(해당하는 경우))이 모두 소진되고 사용량 기반 청구 약관에 서명한 이후에 사용됩니다.

## 임시 평가 크레딧 {#temporary-evaluation-credits}

월별 약정 풀을 구매하지 않았거나 온디맨드 크레딧에 대한 사용량 기반 청구 약관에 동의하지 않은 경우, GitLab Duo Agent Platform 기능을 평가할 수 있는 무료 임시 크레딧 풀을 요청할 수 있습니다.

평가를 위해 요청한 사용자 수에 따라 크레딧이 할당되며, 해당 사용자들을 위한 공유 풀에 추가됩니다. 크레딧은 30일 동안 유효하며, 만료된 후에는 사용할 수 없습니다.

크레딧을 요청하려면 [영업팀에 문의하세요](https://about.gitlab.com/sales/).

Free 티어를 사용 중이고 크레딧을 사용해보려면 [Ultimate 평가판](free_trials.md)을 시작할 수 있습니다.

## GitLab Credits 구매 {#buy-gitlab-credits}

고객 포털에서 월별 약정 풀에 사용할 GitLab Credits를 구매할 수 있습니다.

{{< tabs >}}

{{< tab title="고객 포털" >}}

사전 요구 사항:

- 청구 계정 관리자여야 합니다.

1. [고객 포털](https://customers.gitlab.com/)에 로그인합니다.
1. 관련 구독 카드에서 **GitLab Credits 대시보드**를 선택합니다.
1. **월간 약정 구매** 또는 **월간 약정 증가**를 선택합니다.
1. 구매할 크레딧 수를 입력합니다.
1. **주문 검토**를 선택합니다. 크레딧 수량, 고객 정보 및 결제 수단이 정확한지 확인합니다.
1. **구매 확인**을 선택합니다.

{{< /tab >}}

{{< tab title="GitLab.com" >}}

사전 요구 사항:

- 그룹의 소유자 역할이 있어야 합니다.

Premium 및 Ultimate 티어의 경우:

1. 상단 바에서 **검색 또는 이동**을 선택하고 최상위 그룹을 찾습니다.
1. **설정** > **GitLab 크레딧**을 선택합니다.
1. **월간 약정 구매** 또는 **월간 약정 증가**를 선택합니다.
1. 고객 포털 양식에서 구매하려는 크레딧 수를 입력합니다.
1. **주문 검토**를 선택합니다. 크레딧 수량, 고객 정보 및 결제 수단이 정확한지 확인합니다.
1. **구매 확인**을 선택합니다.

Free 티어의 경우:

1. 상단 바에서 **검색 또는 이동**을 선택하고 최상위 그룹을 찾습니다.
1. **설정** > **청구**를 선택합니다.
1. 다음 조건에 해당하는 경우:
   - 평가판을 사용 중이 아닌 경우: GitLab Credits 카드에서 **크레딧 구매** 또는 **크레딧 증가**를 선택합니다.
   - 활성 평가판을 사용 중인 경우: GitLab Credits 카드에서 **월간 약정 구매** 또는 **크레딧 증가**를 선택합니다.
1. 고객 포털 양식에서 구매하려는 크레딧 수를 입력합니다.
1. **주문 검토**를 선택합니다. 크레딧 수량, 고객 정보 및 결제 수단이 정확한지 확인합니다.
1. **구매 확인**을 선택합니다.

{{< /tab >}}

1. 고객 포털 양식에서 구매하려는 크레딧 수를 입력합니다.
1. **주문 검토**를 선택합니다. 크레딧 수량, 고객 정보 및 결제 수단이 정확한지 확인합니다.
1. **구매 확인**을 선택합니다.

Free 티어의 경우:

1. 오른쪽 위 모서리에서 **관리자**을 선택합니다.
1. 왼쪽 사이드바에서 **구독**을 선택합니다.
1. GitLab Credits 카드에서 **크레딧 구매**를 선택합니다.
1. 고객 포털 계정이 없는 경우, 먼저 계정 만들기 단계를 완료합니다. 그런 다음 자격 증명을 사용하여 로그인합니다.
1. 고객 포털 양식에서 구매하려는 크레딧 수를 입력합니다.
1. **주문 검토**를 선택합니다. 크레딧 수량, 고객 정보 및 결제 수단이 정확한지 확인합니다.
1. **구매 확인**을 선택합니다.

## 크레딧 배수 {#credit-multipliers}

크레딧 사용량은 사용자가 이용하는 기능과 모델을 기준으로 계산됩니다. 일부 기능은 선택할 수 있는 여러 모델 옵션이 제공되는 반면, 다른 기능은 단일 모델만 사용합니다.

요청은 사용자가 시작한 단일 청구 가능 작업(예: 채팅 메시지 전송 또는 코드 생성 요청)을 의미합니다. 사용자의 관점에서 하나의 상호 작용을 나타냅니다.

모델 호출은 사용자 요청을 처리하기 위해 LLM으로 수행되는 백엔드 API 호출을 나타냅니다. 단일 사용자 요청이 여러 번의 모델 호출을 트리거할 수 있습니다. 예를 들어, 컨텍스트를 이해하기 위한 한 번의 호출과 응답을 생성하기 위한 또 다른 호출입니다.

### 모델 {#models}

다음 표는 다양한 [모델](../user/duo_agent_platform/model_selection.md)에 대해 1 GitLab Credit으로 수행할 수 있는 LLM 호출 횟수를 보여줍니다. 더 새롭고 복잡한 모델일수록 배수가 높으며 더 많은 크레딧을 요구합니다.

모델 사용 요금은 다음 청구 방식에 따라 부과됩니다.

- GitLab 관리형 모델의 가변 가격 책정: 하나의 요청은 단일 LLM 호출과 같습니다. 하나의 플로우는 한 번 또는 여러 번의 호출을 수행합니다. 크레딧 비용은 사용된 모델에 따라 달라집니다.
- 자체 호스팅 모델의 가변 가격 책정: 하나의 요청은 단일 LLM 호출과 같습니다. 하나의 플로우는 한 번 또는 여러 번의 호출을 수행합니다. [지원되거나](../administration/gitlab_duo_self_hosted/supported_models_and_hardware_requirements.md#supported-models) [호환되는](../administration/gitlab_duo_self_hosted/supported_models_and_hardware_requirements.md#compatible-models) 모든 자체 호스팅 모델의 경우 1 크레딧으로 8개의 요청을 수행할 수 있습니다.
- GitLab Duo 기능의 정액 가격 책정:  엔드투엔드 실행이 소비될 때마다 실행 중에 수행된 LLM 호출 수(GitLab 관리형 및 자체 호스팅 모델 포함)에 관계없이 미리 설정된 크레딧 양이 차감됩니다. 자체 호스팅 모델에서 실행되는 기능은 실행을 위해 소비된 크레딧에 대해 20% 할인을 받습니다.
- 실패한 실행에 대한 크레딧 차감은 제공 서비스에 따라 다릅니다.
  - GitLab.com에 GitLab 관리 모델에서는 완료되기 전에 실패한 플로우는 일부 LLM 호출이 이미 수행되었더라도 크레딧이 차감되지 않습니다.
  - GitLab Self-Managed에 자체 호스팅 모델에서 정액 요금을 사용하지 않는 기능의 경우 청구는 플로우 완료가 아닌 개별 LLM 호출을 기반으로 합니다. 각 호출은 시작할 때 계수되므로 플로우가 실패하기 전에 수행한 호출은 여전히 청구됩니다. 즉, 중간에 실패한 플로우는 이미 시작된 호출에 대한 크레딧을 계속 소비할 수 있습니다. 정액 요금 기능의 경우 실제로 수행된 LLM 호출의 수와 관계없이 플로우가 실패하더라도 전체 정액 요금이 청구됩니다.

## GitLab Credits 대시보드 {#gitlab-credits-dashboard}

{{< details >}}

- 제공 서비스: GitLab.com, GitLab Self-Managed

{{< /details >}}

{{< history >}}

- GitLab 18.7에서 도입되었습니다.
- 정렬 결과 기능은 GitLab 18.10에서 [도입](https://gitlab.com/groups/gitlab-org/-/work_items/21008)되었습니다.

{{< /history >}}

GitLab Credits 대시보드는 GitLab Credits 사용량에 대한 정보를 표시합니다. 대시보드를 사용하여 크레딧 소비를 모니터링하고 추세를 추적하며 사용 패턴을 파악하세요.

크레딧 소비 관리를 돕기 위해 GitLab은 관리자 및 구독 소유자에게 다음 정보를 이메일로 발송합니다.

- 월별 크레딧 사용량 요약
- 크레딧 사용량이 임계값의 50%, 80%, 100%에 도달했을 때의 알림

고객 포털 및 GitLab에서 대시보드에 액세스할 수 있습니다.

> [!note]
> 사용량 데이터는 실시간으로 표시되지 않습니다. 데이터는 주기적으로 대시보드와 동기화되므로, 사용량 데이터는 실제 소비 후 몇 시간 이내에 표시됩니다. 즉, 대시보드에 최근 사용량이 표시되지만 지난 몇 시간 동안 수행된 작업은 반영되지 않을 수 있습니다.

### 고객 포털 {#in-customers-portal}

고개 포털의 GitLab Credits 대시보드는 사용량 및 비용에 대한 가장 자세한 정보를 제공합니다.

대시보드에서 '사용한 크레딧'은 사용 가능한 크레딧에서 차감된 수를 나타냅니다. 초과분(온디맨드 크레딧)의 경우, 사용량 기반 청구 약관에 동의했다면 '사용한 크레딧'은 나중에 지불하게 될 온디맨드 사용량을 나타냅니다.

대시보드에는 주요 지표의 요약 카드가 표시됩니다.

- 이번 달 사용량: 이번 달에 사용된 총 GitLab Credits (월간 약정이 있는 경우)
- 포함된 크레딧: 구독에 포함된 총 크레딧 (월간 약정이 있는 경우)
- 약정된 크레딧: 월간 약정 풀의 크레딧 (해당하는 경우)
- 월별 면제: 면제 혜택 중 남은 크레딧 (해당하는 경우)
- 온디맨드 사용량: 포함된 크레딧 및 약정된 금액을 초과하여 소비된 크레딧입니다. 모든 온디맨드 크레딧을 상쇄할 수 있는 충분한 면제 크레딧이 있는 경우, GitLab Credits 대시보드는 **온디맨드** 카드를 숨기고 대신 **월간 면제** 카드를 표시합니다.
- 사용 제어 상태: 사용자별 크레딧 상한에 도달하여 개별 사용자의 Agent Platform 액세스가 차단되었는지 여부입니다.

### GitLab에서 {#in-gitlab}

> [!note]

>

GitLab 내의 GitLab Credits 대시보드는 조직의 크레딧 사용에 대한 운영 가시성을 제공합니다. 대시보드를 사용하여 어떤 사용자, 그룹 또는 프로젝트가 사용량을 발생시키는지 파악하고, 리소스 할당에 대해 정보에 기반한 의사결정을 내리세요.

대시보드에는 다음 정보가 표시됩니다.

- **조직 사용량**:  GitLab 인스턴스 또는 그룹 전체의 총 크레딧 사용량, 활성 사용자, 일일 크레딧 평균 및 최대 하루 사용량
- **총 크레딧 소비**:  모든 제품에 대한 일일 크레딧 소비량(막대 차트로 표시됨)
- **사용자별 사용량**: 각 사용자별 사용 크레딧 수
- **사용자 드릴다운 보기**:  각 사용자의 개별 사용 이벤트(GitLab Duo Agent Platform 세션 세부 정보 링크 포함)
- **제품별 사용량**: GitLab Duo Agent Platform 및 Secrets Manager에 사용된 크레딧 수 및 총 크레딧의 백분율

> [!note]
> [GitLab Secrets Manager](../ci/secrets/secrets_manager/_index.md)가 베타 버전인 동안 GitLab에서는 사용에 대한 요금을 청구하지 않습니다. Secrets Manager는 크레딧 대시보드에 표시되지만 베타 기간이 끝날 때까지 사용 데이터를 표시하지 않습니다.

### 사람이 아닌 주체의 사용량 {#non-human-subject-usage}

{{< history >}}

- GitLab 19.0에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/work_items/596238)되었습니다.

{{< /history >}}

크레딧 소비는 실제 사용자 또는 사람이 아닌 주체(예: SAST False Positive Detection 플로우와 같은 AI 기능)에 의해 트리거될 수 있습니다.

크레딧 소진 위치를 파악하는 데 도움이 되도록, GitLab Credits 대시보드의 **사용자별 사용** 탭에는 사람이 아닌 주체를 나타내는 행 옆에 **자동화된 플로우** 배지가 표시됩니다. 배지가 없는 행은 실제 사용자를 나타냅니다.

**자동화된 플로우** 배지의 표시는 **GitLab Credits 사용자 데이터 표시** 설정에 의해 제어되며 [그룹](../user/group/manage.md#display-gitlab-credits-user-data) 및 [인스턴스](../administration/settings/visibility_and_access_controls.md#display-gitlab-credits-user-data)에서 사용할 수 있습니다.

예상치 못한 초과 요금을 방지하기 위해 구독 및 사용자 수준에서 월별 GitLab Credits 상한을 설정할 수 있습니다. 크레딧 소비량이 설정된 상한에 도달하면, 다음 청구 기간이 시작되거나 관리자가 상한을 조정 또는 사용 중지할 때까지 GitLab Credits를 소비하는 기능(예: GitLab Duo Agent Platform)에 대한 액세스가 자동으로 일시 중단됩니다.

다음 상한 유형을 사용할 수 있습니다.

| 상한 유형 | 적용 대상 | 계산하는 크레딧 소스 | 관리 수단 |
|---|---|---|---|
| 구독 상한 | 구독의 모든 사용자 | 온디맨드 전용 | 고객 포털 |
| 정액 사용자 상한 | 개별 사용자(기본 제한) | 모두 | GraphQL API |
| 사용자별 재정의 | 포함된 크레딧을 포함한 특정 사용자의 총 사용량입니다. 정액 상한을 무시합니다. 따라서 사용자는 포함된 할당량 또는 상한 중 더 높은 양까지 소비할 수 있습니다. | 모두 | GraphQL API |

현재 청구 기간의 주문형 사용량이 구성된 상한에 도달하거나 초과하면 해당 구독 또는 인스턴스의 모든 사용자에 대해 모든 Agent Platform 기능(Duo Chat, Code Suggestions, Flows 및 Agents)이 일시 중단되고 GitLab에서 청구 계정 관리자에게 이메일 알림을 보냅니다. 사용자 수준 상한의 경우, 상한에 도달한 개별 사용자만 이용이 중단됩니다.

정액 사용자 상한과 사용자별 재정의 상한은 사용자의 포함된 할당량 초과 사용량에 적용됩니다. 사용자는 여전히 포함된 크레딧을 보유하지만 사용량이 상한에 도달한 후에도 계속 포함된 크레딧을 소비할 수 있습니다. 상한은 사용자의 포함된 크레딧이 소진된 후에만 적용됩니다.

상한에 도달한 사용자는 상한이 상향 조정되거나 다음 청구 기간이 시작될 때까지 Agent Platform 기능에 액세스할 수 없습니다.

사용량 카운터는 각 청구 기간이 시작될 때 자동으로 초기화됩니다. 상한 값은 변경되지 않는 한 청구 기간이 바뀌어도 계속 유지됩니다.

상한은 사용 가능한 최신 사용량 데이터를 기준으로 적용됩니다. 데이터가 실시간으로 반영되지 않으므로, 제한 조치가 발효되기 전에 약간의 추가 GitLab Credits 사용이 발생할 수 있습니다.

상한은 사용자가 포함된 GitLab Credits를 소비하는 것을 방지하지 않습니다. 적용은 사용자별로 시작되며 해당 사용자의 포함된 할당량이 소진된 후에만 시작됩니다. 이 시점까지는 `0`의 상한을 포함하여 상한 값에 관계없이 사용자는 전체 GitLab Duo Agent Platform 액세스 권한을 유지합니다.

포함된 잔액에 관계없이 모든 GitLab Credits 소비를 즉시 중지하려면 영향을 받는 사용자 또는 네임스페이스에 대해 GitLab Duo를 사용으로 중지합니다.

상한 값이 적용되는 방식은 상한 유형에 따라 다릅니다.

- **구독 수준 상한**은 온디맨드 사용량에만 적용됩니다. 상한은 구독 전체에서 온디맨드 사용량에 대해 모든 사용자의 포함된 크레딧 위에 허용되는 양입니다.
- **사용자별 상항**은 포함된 크레딧을 포함한 사용자의 총 사용량에 적용됩니다. 따라서 사용자는 포함된 할당량 또는 상한 중 더 높은 양까지 소비할 수 있습니다.

#### 예제 {#examples}

구독 수준 상한의 경우 각각 100개의 포함된 GitLab Credits가 있는 10명의 사용자가 있는 구독을 고려하세요. 청구 계정 관리자가 구독 수준 온디맨드 상한을 `0`(으)로 설정합니다.

- 포함된 크레딧 100개를 모두 사용한 사용자는 추가 사용량이 온디맨드가 되기 때문에 즉시(다음 적용 검사 시) Agent Platform 기능에서 차단됩니다.
- 포함된 크레딧 중 40개만 사용한 사용자는 계속해서 Agent Platform 기능을 사용할 수 있으며 남은 포함된 크레딧 60개를 소비할 수 있습니다. `0` 상한은 아직 이들에게 적용되지 않습니다.

사용자별 상한의 경우 24개의 포함된 GitLab Credits를 보유한 사용자를 고려하세요.

- 사용자별 상한 `50`의 경우 사용자는 포함된 할당량 26개 크레딧을 넘어 총 50개의 크레딧 후에 차단됩니다.
- 사용자별 상한 `10`의 경우 사용자는 포함된 할당량이 소진될 때 즉 24개의 크레딧 후에 차단됩니다.

#### 구독 수준 사용 상한 설정 {#set-a-subscription-level-usage-cap}

사전 요구 사항:

- 청구 계정 관리자여야 합니다.

1. [고객 포털](https://customers.gitlab.com/)에 로그인합니다.
1. 구독 카드에서 **GitLab Credits 대시보드**를 선택합니다.
1. **사용 제어**를 선택합니다.
1. **온디맨드 크레딧 상항** 패널에서 **온디맨드 크레딧 상한 설정** 토글을 켭니다.
1. 청구 기간당 허용되는 최대 온디맨드 GitLab Credits 수량을 입력합니다.
1. **변경 사항 저장**을 선택합니다.

현재 청구 기간에 대해 이미 보고된 총 온디맨드 사용량보다 낮게 상한을 설정하면, 다음 적용 여부 확인 시 즉시 상한에 도달한 것으로 간주됩니다.

상한을 사용 중지하려면 **온디맨드 크레딧 상한 설정** 토글을 끕니다. 사용 중지하면 구독 수준의 온디맨드 GitLab Credits 상한이 적용되지 않으며, 동작 방식은 기존의 청구 방식으로 되돌아갑니다.

GraphQL API를 사용하여 [사용 상한을 확인](../api/graphql/reference/_index.md#gitlabsubscriptionbudgetcaps)하거나 [정액 사용자 수준 상한](../api/graphql/reference/_index.md#mutationupsertflatusercap) 또는 [사용자별 상한 재정의](../api/graphql/reference/_index.md#mutationupsertuserbudgetcapoverrides)을 설정할 수 있습니다.

### 사용 제어 상태 {#usage-control-status}

{{< history >}}

- GitLab 18.11에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/work_items/594635)되었습니다.

{{< /history >}}

사용자별 크레딧 상한이 사용되면, GitLab Credits 대시보드의 **사용자별 사용량** 탭에 **사용량 제어 상태** 열이 표시됩니다. 이 열은 각 사용자가 [GitLab Duo Agent Platform](../user/duo_agent_platform/_index.md) 기능에 액세스할 수 있는지, 아니면 크레딧 상한에 도달하여 차단되었는지 여부를 보여줍니다.

**사용량 제어 상태** 열에 GitLab에서 사용자에게 상한을 적용할 때만 상태 **차단됨**을 표시합니다. GitLab은 사용자의 포함된 크레딧이 소진된 후에 상한을 적용합니다. 상한에 도달했지만 여전히 포함된 크레딧이 있는 사용자는 포함된 크레딧을 계속 소비할 수 있기 때문에 상태가 **일반**입니다.

이 열에는 다음 상태 중 하나가 표시됩니다.

| 상태 | 설명 |
|--------|-------------|
| **일반** | 사용자가 크레딧 상한에 도달하지 않았거나 상한에 도달했지만 여전히 포함된 크레딧이 있으며 GitLab Duo Agent Platform 기능을 사용할 수 있습니다. |
| **차단됨 - 구독 상한에 도달됨** | 사용자가 구독 수준에서 설정된 정액 사용자별 상한에 도달했습니다. |
| **차단됨 - 사용자 상한에 도달됨** | 사용자가 해당 사용자에게 개별적으로 설정된 사용자별 재정의 상한에 도달했습니다. |

#### 크레딧 상한에 도달한 사용자 차단 해제 {#unblock-a-user-who-reached-their-credit-cap}

사용자별 재정의 GraphQL API를 사용하여 차단된 사용자의 액세스 권한을 복원할 수 있습니다.

사용자의 차단을 해제하려면 다음 중 하나를 수행합니다.

- 상한 증가: 사용자의 사용량이 새로운 제한치 미만이 되도록 더 높은 사용자별 재정의 상한을 설정합니다.
- 상한 제거:  사용자별 재정의를 삭제하여 해당 사용자가 더 이상 개별 상한의 적용을 받지 않도록 합니다.

상한을 업데이트하면 사용자의 상태가 **일반**으로 변경되며 GitLab Duo Agent Platform 기능을 다시 사용할 수 있습니다.

### 사용자 크레딧 사용량 세부 정보 보기 {#view-user-credit-usage-details}

{{< history >}}

- GitLab Duo Agent Platform 세션 상세 정보 연결 기능은 GitLab 18.10에서 [도입](https://gitlab.com/gitlab-org/gitlab/-/issues/579139)되었습니다.

{{< /history >}}

드릴다운 보기에서 사용자의 개별 사용 이벤트를 확인하려면 다음을 수행합니다.

1. GitLab Credits 대시보드에서 **사용자별 사용** 탭을 선택합니다.
1. **사용자** 열에서 확인하려는 사용자를 선택합니다.
1. 세션 상세 정보를 확인하려면 **작업** 열에서 확인하려는 작업을 선택합니다.

> [!note]
> 세션 링크는 프로젝트에서 발생하고 세션 ID가 연결된 GitLab Duo Agent Platform 사용 이벤트에 대해서만 제공됩니다. 그룹에서 발생한 사용 이벤트, 레거시 이벤트 및 Agent Platform 외부 작업에는 링크가 제공되지 않습니다.
