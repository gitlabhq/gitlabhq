title: ファイルのロック

ファイルのロックを使用すると、複数のユーザーが同じファイルを同時に編集するのを防ぐことができ、マージコンフリクトの回避に役立ちます。ファイルのロックは、デザインファイル、動画、その他のテキスト以外のコンテンツなど、マージできないバイナリファイルで特に有用です。

GitLabでは、2種類のファイルのロックをサポートしています:

- 排他的ファイルのロック: Git LFSと[`.gitattributes`](repository/files/git_attributes.md)を使ったコマンドラインで適用されます。これらのロックは、どのブランチ上でもロックされたファイルの変更を防ぎます。Free、Premium、およびUltimateプランで利用可能です。詳細については、[排他的ファイルロック](../../topics/git/file_management.md#exclusive-file-locks)を参照してください。
- デフォルトブランチのファイルおよびディレクトリロック: GitLab UIを通じて適用されます。これらのロックは、デフォルトブランチ上のファイルおよびディレクトリの変更のみを防ぎます。

## デフォルトブランチのファイルおよびディレクトリロック {#default-branch-file-and-directory-locks}

{{< details >}}

- プラン: Premium、Ultimate
- 提供形態: GitLab.com、GitLab Self-Managed、GitLab Dedicated

{{< /details >}}

デフォルトブランチロックは、プロジェクトの[デフォルトブランチ](repository/branches/default.md)設定にのみ適用されます。これらのロックは、他のブランチでの共同作業者のワークフローをブロックすることなく、デフォルトブランチの安定性を維持するのに役立ちます。

ファイルまたはディレクトリがユーザーによってロックされている場合:

- ロックを作成したユーザーのみが、デフォルトブランチ上のファイルまたはディレクトリを変更できます。
- 他のユーザーにとって、ロックされたファイルまたはディレクトリはデフォルトブランチ上で読み取り専用です。
- デフォルトブランチ上のロックされたファイルまたはディレクトリへの直接の変更はブロックされます。
- ロックされたファイルまたはディレクトリを変更するマージリクエストは、デフォルトブランチにマージできません。

> [!note]
> デフォルト以外のブランチでは、すべてのユーザーが引き続きロックされたファイルやディレクトリを変更できます。これらのファイルやディレクトリには、**ロック**ステータスが表示されます。これにより、チームメンバーは他のブランチでのワークフローを制限することなく、進行中の作業を認識できます。
>
> ファイルのロックは、フォーク同期中もバイパスされます。アップストリームプロジェクトから[フォークを更新](repository/forking_workflow.md#update-your-fork)すると、フォーク内のロックされたファイルはアップストリームプロジェクトの変更で上書きされる可能性があります。

### 権限 {#permissions}

デフォルトブランチのロックを作成、表示、または管理するには、プロジェクトのデベロッパー、メンテナー、またはオーナーロールが必要です。詳細については、[ロールと権限](../permissions.md)を参照してください。

### ファイルまたはディレクトリをロック {#lock-a-file-or-directory}

{{< history >}}

- GitLab 17.10で`blob_overflow_menu`[機能フラグ](../../administration/feature_flags/_index.md)とともに[導入](https://gitlab.com/gitlab-org/gitlab/-/issues/519325)されました。デフォルトでは無効になっています。
- GitLab 18.1で[一般提供](https://gitlab.com/gitlab-org/gitlab/-/issues/522993)になりました。機能フラグ`blob_overflow_menu`は削除されました。
- GitLab 19.4で`repository_lock_information`[機能フラグ](../../administration/feature_flags/_index.md)とともにロックボタンが[変更](https://gitlab.com/gitlab-org/gitlab/-/issues/545279)されました。デフォルトでは有効になっています。

{{< /history >}}

> [!flag]
> この機能の利用可否は、機能フラグによって制御されます。詳細については、履歴を参照してください。

ファイルまたはディレクトリをロックするには:

1. 上部のバーで、**検索または移動先**を選択して、プロジェクトを見つけます。
1. ロックしたいファイルまたはディレクトリに移動します。
1. 右上隅で**ロック**を選択します。
1. 確認ダイアログで、**ロック**を選択します。

ボタンが**ロック中**に変わります。ファイルまたはディレクトリを誰がいつロックしたかを表示するには、**ロック中**を選択します。

ディレクトリ内にファイルまたはディレクトリがすでにロックされている場合、そのディレクトリをロックすることはできません。親ディレクトリがロックされている場合、ディレクトリのロックを解除することはできません。どちらの場合も、ボタンは**ロック中**と表示され、関連するロックの詳細が説明されます。ロックされたファイルまたはディレクトリを表示するには、**ロックを表示**を選択します。

**ロック**が表示されない場合、ファイルまたはディレクトリをロックするための必要な権限がありません。

### ロックされたファイルを表示 {#view-locked-files}

ロックされたファイルを表示するには:

1. 上部のバーで、**検索または移動先**を選択して、プロジェクトを見つけます。
1. 左側のサイドバーで、**コード** > **ロックされたファイル**を選択します。

**ロックされたファイル**ページには、Git LFS排他的ロックまたはGitLab UIのいずれかでロックされたすべてのファイルが表示されます。

### ファイルロックを削除 {#remove-file-locks}

前提条件: 

- 次のいずれかの条件を満たす必要があります。
  - ロックを作成したユーザーであること。
  - プロジェクトのメンテナーまたはオーナーロールを持っていること。

ロックを解除するには:

{{< tabs >}}

{{< tab title="ファイルまたはディレクトリから" >}}

1. 上部のバーで、**検索または移動先**を選択して、プロジェクトを見つけます。
1. ロックを解除したいファイルまたはディレクトリに移動します。
1. **ロック中**を選択します。
1. **ファイルのロックを解除**または**ディレクトリのロックを解除**を選択します。
1. 確認ダイアログで、**ロック解除**を選択します。

{{< /tab >}}

{{< tab title="ロックされたファイルページから" >}}

1. 上部のバーで、**検索または移動先**を選択して、プロジェクトを見つけます。
1. 左側のサイドバーで、**コード** > **ロックされたファイル**を選択します。
1. ロックを解除したいファイルの右側で、**ロック解除**を選択します。
1. 確認ダイアログで、**OK**を選択します。

{{< /tab >}}

{{< /tabs >}}

排他的ファイルロックを解除するには、[ファイルをロックおよびロック解除](../../topics/git/file_management.md#lock-and-unlock-files)を参照してください。

## マージリクエストのチェックとロック所有権 {#merge-request-checks-and-lock-ownership}

ロックされたファイルまたはディレクトリへの変更を含むマージリクエストがマージされるように設定されている場合、GitLabはマージリクエストの作成者がロックのオーナーであるかどうかをチェックします。GitLabは個々のコミット作成者をチェックしません。

例: 

- マージリクエストの作成者がファイルまたはディレクトリをロックしたユーザーと同じである場合、そのマージリクエストはマージできます。
- マージリクエストの作成者がロックのオーナーと異なる場合、そのマージリクエストはブロックされます。

> [!note]
> マージリクエストの作成者以外のユーザーは、ロックされたファイルやディレクトリを更新または変更する変更をマージリクエストブランチにプッシュできます。ロックチェックはマージリクエストの作成者のみを考慮するため、マージリクエストはブロックされません。

ロックされたファイルへの不正な変更を防ぐには:

- マージする前にレビューを必要とする[マージリクエスト承認ルール](merge_requests/approvals/rules.md)を使用します。
- ロックされたファイルへのマージリクエストを監視し、承認された変更のみが含まれるようにします。
- 既存のマージリクエストブランチにプッシュする権限を持つユーザーが誰であるかをワークフローで考慮してください。
