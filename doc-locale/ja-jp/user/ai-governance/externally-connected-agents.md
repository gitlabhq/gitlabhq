> [!flag]
> この機能の利用可否は、機能フラグによって制御されます。詳細については、履歴を参照してください。

Claude Code、Cursor、Codexなどのコーディングエージェントが開発者のコンピューターで実行されている場合、AIガバナンスダッシュボードは、GitLab CLI（`glab`）を介してこれらを外部接続エージェント（ECA）として表示できます。

GitLab CLI（`glab`）は各エージェントのローカルトランスクリプトを読み取り、セッションとそのイベントを、エージェントが作業したGitLabプロジェクトに送信します。その後、セッションは次の場所に表示されます:

- [AIガバナンスダッシュボード](governance-dashboard.md)
- AI監査イベントレポート

> [!warning]
> この機能は[ベータ版](../../policy/development_stages_support.md)です。予告なく変更される場合があります。詳細については、[GitLabテスト規約](https://handbook.gitlab.com/handbook/legal/testing-agreement/)を参照してください。

`glab`は、エージェントが実行されたフォルダーのGitリモートからプロジェクトを検出します:

- Claude Codeの場合、`glab`は他のコマンドと同じ方法でリモートを選択します。つまり、`glab`は`glab repo set-default`で設定されたリモートを使用し、設定されていない場合は`upstream`、次に`gitlab`、次に`origin`を使用します。フォークのチェックアウトでは、Claude Codeのセッションはアップストリームプロジェクトに送られます。
- Codexの場合、`glab`はCodexが記録したリポジトリURLを使用し、記録されていない場合は`origin`を使用します。
- Cursorの場合、`glab`は`origin`を使用します。

リモートは、`glab`がサインインしているGitLabインスタンスを指している必要があります。このようなリモートがないフォルダー内のセッションは送信されません。

## 前提条件 {#prerequisites}

- トップレベルグループに対して、GitLab Duo Agent Platformを備えたGitLab PremiumまたはUltimate。
- [`glab`](../../editor_extensions/gitlab_cli/_index.md) 1.122.0以降で、GitLabインスタンスにサインインしていること。
- プロジェクトに対して少なくともデベロッパーロール。
- トップレベルグループに対して**外部のエージェントを許可**がオンになっていること。デフォルトでオンになっています。この設定は、CI/CDパイプラインで実行されるAIカタログの[外部エージェント](../duo_agent_platform/agents/external.md#turn-external-agents-on-or-off)に属しており、セッションキャプチャも制御します。これをオフにすると、ローカルのコーディングエージェントのセッションも停止します。
- グループまたはプロジェクトに対して[**AI監査イベントを保存**](ai-audit-events.md#enable-ai-audit-event-storage)がオンになっていること。この設定がないと、セッションのみが記録され、そのイベントとツール呼び出しは記録されません。この設定はデフォルトでオフになっています。これを変更するには、オーナーまたはセキュリティマネージャーロールが必要です。
- macOSまたはLinuxを実行しているコンピューター。

## セッションキャプチャを設定する {#set-up-session-capture}

エージェントを実行する各コンピューターのユーザーアカウントごとに、セッションキャプチャを1回設定します。このセクションのコマンドは、[`glab govern`のリファレンス](https://docs.gitlab.com/cli/govern/)に記載されています。

`glab govern setup`は常にClaude Codeフックをインストールします。`--agents`オプションを指定すると、`glab`は確認を求めた上でClaude Codeフックもインストールします。スクリプトから`glab`を呼び出す場合は、`--yes`を渡してください。

### Claude Codeセッションをキャプチャする {#capture-claude-code-sessions}

Claude Codeセッションはフックを通じてキャプチャされ、フックから`glab`がサインインできる場合は、各返信後にセッションを送信します。バックグラウンドジョブは、フックが見逃したものを送信します。

Claude Codeセッションをキャプチャするには、次を実行します:

```shell
glab govern setup
```

このコマンドは次をインストールします:

- `~/.claude/settings.json`内のStopフックとSessionEndフック。フックは、返信のたびにセッションを送信し、セッションが終了すると完了としてマークします。
- 30分ごとに実行されるバックグラウンドジョブ。このジョブは、フックが見逃したものを送信し、24時間アクティビティがないセッションを完了としてマークします。macOSでは、このジョブは`launchd`エージェントであり、Linuxでは`systemd`ユーザータイマーです。

コマンドを実行する前に終了したセッションは送信されません。

### CursorおよびCodexセッションをキャプチャする {#capture-cursor-and-codex-sessions}

`glab`は、CursorおよびCodexのフックをインストールしません。バックグラウンドジョブは、`~/.cursor/projects`と`~/.codex/sessions`を30分ごとにスキャンして、これらのセッションを検出します。

CursorおよびCodexセッションをキャプチャするには、次を実行します:

```shell
glab govern setup --agents codex,cursor
```

このジョブは、過去89日以内にアクティブで、`glab`がサインインしているGitLabインスタンス上のプロジェクトに属している場合、コマンドを実行する前のセッションも送信します。セッションは、24時間アクティビティがないと完了としてマークされます。カスタムの`CODEX_HOME`フォルダーに保存されているCodexセッションは検出されません。

キャプチャするエージェントを変更するには、異なる`--agents`リストでコマンドを再実行します。CursorおよびCodexセッションのキャプチャを停止するには、`--agents ""`を指定して実行します。

### セットアップを確認する {#verify-the-setup}

セッションキャプチャが正しく設定されていることを確認するには、次を実行します:

```shell
glab govern doctor
```

このコマンドは次を行います:

- `glab`がデフォルトのGitLabホストにサインインしていること、および`PATH`内にあることを確認します。
- Claude Codeフックが`~/.claude/settings.json`内にあること、およびGitLab APIに到達可能であることを確認します。
- バックグラウンドジョブがインストールされているかどうか、および前回の実行状況を報告します。
- 失敗した各チェックについて、修正方法を説明します。

最終実行の行には次が一覧表示されます:

- セッションキャプチャが有効になっていないプロジェクト。
- GitLabが拒否したエージェントタイプ。
- `glab`がスキップしたCursorセッション。

このコマンドは、グローバルな`~/.claude/settings.json`のみを読み取ります。プロジェクトの`.claude`フォルダー内のフックは見つからないと報告され、グローバルなStopフックがない場合、バックグラウンドジョブはClaude Codeセッションをスキップします。

バックグラウンドジョブを待たずに今すぐセッションを送信するには、次を実行します:

```shell
glab govern audit sync --all
```

## 送信されるデータ {#data-that-is-sent}

各セッションについて、`glab`は次を送信します:

- 入力したプロンプト。8 KBを超えるプロンプトは切り詰められます。最初のプロンプトは、セッションのゴールにもなります。
- コマンド、ファイルパス、編集内容など、引数を含む各ツール呼び出し。8 KBを超える引数はマーカーに置き換えられます。
- 各ツール呼び出しの結果、所要時間、およびエラーメッセージ。エラーメッセージは255文字で切り詰められます。
- 各応答のモデルとトークン使用量。
- セッションが完了すると、トランスクリプトファイルのチェックサム。

ツールの出力と応答のテキストは送信されませんが、失敗したツール呼び出しの出力の最初の255文字はエラーメッセージとして送信されます。コンピューターを識別するために、`glab`はハッシュ化されたマシンIDを送信します。

エージェントによって記録される詳細は異なります:

| エージェント | Claude Codeとの違い |
|-------|---------------------------|
| Codex | Codexは成功したかどうかを記録しないため、すべてのツール呼び出しの結果はエラーメッセージなしで完了として記録されます。 |
| Cursor | Cursorは結果、トークン使用量、タイムスタンプを記録しないため、プロンプトとツール呼び出しのみが送信されます。イベントは、トランスクリプトの最終更新日時によってタイミングが決まります。 |

## ECAセッションを表示する {#view-eca-sessions}

外部接続エージェント（ECA）からのセッションは、**表示**コントロールが**全てのエージェント**（デフォルト）または**接続済み**に設定されている場合、AIガバナンスダッシュボードに表示されます:

- **最近のセッション**カードには、各セッションがそのエージェントの名前で表示されます。例: **Cursor (glab)**または**Claude Code (glab)**。
- **最もよく使用されるエージェント**カードには、実行したマシン数とユーザー数とともに、接続されている各エージェントが一覧表示されます。例: **2 machines · 2 users**。
- KPIタイルおよびその他のカードは、GitLab Duo Agent Platformのセッションと合わせて、セッションとツール呼び出しをカウントします。

セッションとそのイベントは、AI監査イベントレポートにも一覧表示されます:

- Claude Codeセッションは最初の返信の直後に表示され、エージェントを終了すると完了としてマークされます。終了フックが実行されなかった場合、バックグラウンドジョブは24時間アクティビティがないとセッションを完了としてマークします。
- CursorおよびCodexセッションは通常、コンピューターの電源が入っていてサインインしている状態でエージェントを使用してから30分以内に表示されます。macOSでは、バックグラウンドジョブの初回実行はセットアップから30分後です。これらのセッションは、24時間アクティビティがないと完了としてマークされます。
- ダッシュボードの数値は、少し遅れて更新されます。

## セッションのキャプチャを停止する {#stop-capturing-sessions}

バックグラウンドジョブを削除し、CursorおよびCodexセッションのキャプチャを停止するには、次を実行します:

```shell
glab govern setup --uninstall
```

Claude Codeフックはそのまま残ります。Claude Codeセッションのキャプチャを停止するには、`~/.claude/settings.json`の`hooks`セクションから2つの`glab govern audit sync`エントリを削除します。Stopフックがない場合、バックグラウンドジョブもClaude Codeセッションをスキップします。

すでにGitLabに送信されたセッションは、ダッシュボードに残ります。

## トラブルシューティング {#troubleshooting}

| 問題 | 原因 | 解決方法 |
|---------|-------|------------|
| `glab govern doctor`が失敗したチェックを報告します。 | このコンピューターでのセットアップが不完全です。 | チェックが表示する修正方法に従ってください。 |
| `glab govern doctor`の最終実行の行に、あるプロジェクトのセッションキャプチャが有効になっていないと表示されます。 | そのプロジェクトではセッションキャプチャがオフになっています。 | GitLabサポートにお問い合わせください。 |
| `glab govern audit sync --all`が`403 Forbidden`の警告を表示するか、`glab govern doctor`が前回の実行のエラーとして表示します。 | プロジェクトでのロールがデベロッパー未満である、グループがGitLab Duo Agent Platformを持っていない、トップレベルグループで**外部のエージェントを許可**がオフになっている、またはグループのオーナーがこのコンピューターのエージェントIDを失効させています。フォークのチェックアウトでのClaude Codeの場合、セッションはアップストリームプロジェクトに送られました。 | グループのオーナーと一緒にロールと設定を確認してください。フォークのチェックアウトでは、`glab repo set-default`を実行し、セッションの送信先とするプロジェクトを選択してください。 |
| セッションは表示されますが、イベントやツール呼び出しがありません。 | グループまたはプロジェクトで**AI監査イベントを保存**がオフになっています。 | この設定をオンにしてください。オーナーまたはセキュリティマネージャーロールが必要です。変更前のイベントは記録されません。 |
| セッションは送信されましたが、ダッシュボードに表示されません。 | ダッシュボードは、バックグラウンドで処理されるデータを読み取るため、またはフィルターがセッションを除外しているためです。 | **表示**を**全てのエージェント**または**接続済み**に設定し、日付範囲を確認してから、数分待ってページを再読み込みしてください。 |
| Cursorセッションがまったく送信されません。 | `glab`は、セッションが実行されたフォルダーを確認できませんでした。これは、フォルダーが移動した場合、別のフォルダーのパスが句読点のみ異なる場合（例: `code/cli-docs`と`code/cli/docs`）、またはセッションが操作したすべてのファイルがフォルダーの外にある場合に発生します。また、フォルダーに`origin`リモートがない場合にも発生します。 | `glab govern doctor`を実行して、「not synced」の理由を確認してください。セッションが実行されたときの場所にフォルダーを保ち、パスが句読点のみ異なるフォルダーの名前を変更し、フォルダーに`origin`リモートがあることを確認してください。 |
| `glab govern doctor`は、あるエージェントタイプがまだGitLabでサポートされていないと表示します。 | `glab`がセッションを最初に検出したとき、GitLabはそのエージェントタイプを受け入れませんでした。このようなセッションは送信されません。 | GitLabがエージェントタイプを受け入れた後に`glab`が検出したセッションは送信されます。メッセージが解消しない場合は、GitLabサポートにお問い合わせください。 |
